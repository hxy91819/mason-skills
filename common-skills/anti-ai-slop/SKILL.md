# Anti AI Slop

看刚刚改过的代码和文档。有未提交改动就看工作区 diff；已经提交就看那次 commit。自己改到没有 slop，再告诉用户删了什么。

## 看哪里

未指定时先 `git status --short` 和 `git diff HEAD`（含暂存、未跟踪的文本）。工作区干净则 `git show HEAD`。用户点了文件或 commit，就只看那些。

## 什么算 slop

删掉之后代码或文档照样执行得了，多半就是。优先删，不要改写成新许可。

- 禁令删了，换成「可自行 X / 无需授权」
- 还在说解禁、不再禁止、本文不做什么
- 正文复述 frontmatter、yaml 策略、类型或 `--help` 已经写过的话
- 「本页用于」「这里展示」「本节说明」
- 把当次用户原话、会话口吻写进长期文件
- 实现细节、验收/核对目的，写成给读者的介绍
- 注释、help、测试说明在讲「现在允许」
- TODO、调试打印、占位符留在要提交的内容里

工具的 allow/block 清单、仍然有效的约束、行为测试，留着。改写用陈述句写要做什么，不要写不做什么。判不准就留。

看完就改，再看一遍新 diff，直到没有这些问题。不要借机加新策略。

## 报告

改了什么，留下了哪条真约束。没有 slop 就说 clean。
