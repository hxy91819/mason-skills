# 核心知识落点

仅在 `distill` 的项目知识 lane 中，且候选已经通过证据、价值和去重判断后读取本页。目标是让未来的人和 Agent 沿自然任务路径到达一份活的权威说明，而不是积累复盘记录。

## 落点

| 信号 | 权威落点 | 保留的内容 | 不在这里缓存的内容 |
|---|---|---|---|
| 每次任务都必须遵守的行为、风险边界、读取路由 | `AGENTS.md` | 正向约束、何时读取下一份材料、理由只在不可自明时保留 | 实现细节、一次性事故过程 |
| 概念、术语、责任归属和系统 seam | `GLOSSARY.md`（旧约定为 `CONTEXT.md`） | 稳定的领域模型和边界 | API 字段、逐模块实现 |
| “我要做 X，下一步读什么” | 文档索引 | 问题到权威文档/验证入口的路由 | 同一规则的正文副本 |
| 用户可见行为、长期技术选择和操作契约 | 对应领域的规格、架构或操作文档 | 选择、原因、范围、后果和验证入口 | 完整讨论、提交流水 |
| 可重复且判断依赖流程的工作 | Skill；重复的机械动作再下沉到脚本 | 输入、边界、审批、失败路径和验收输出 | 业务决定或领域事实的第二份解释 |
| 可机械检查的行为 | 代码、测试、schema、配置 | 可执行事实 | 文档中的字段、端点或固定数据副本 |

一个候选若无法回答下列五项，就不应沉淀：**结论**、**原因**、**范围**、**权威**和**验证**。其中“权威”是用户确认、已批准来源，或明确标为待确认的 agent 建议；“验证”必须是当前可执行的检查或明确的未来观察点。

## 生命周期

先删除或合并，再增加说明。新规则必须能够从未来任务的入口自然抵达；若需要在多份材料中复制才找得到，优先修正路由。

历史验收、迁移记录和已废弃流程应保留证据边界，但在开头标明“历史证据、不可复用”以及当前权威规范链接。不要把历史结论改写成仍然生效的操作说明。

当可靠脚本、测试、类型、环境隔离或其他执行性约束已经承担了某个事实时，文档只保留意图、理由和入口。下一次复盘若发现同样的内容，判断它是 **Live**、**Superseded** 或 **Duplicate**，而不是再创建一层摘要。
