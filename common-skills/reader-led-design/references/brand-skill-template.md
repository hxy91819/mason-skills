# 把客户 VI 规范写成专案 skill

[reader-led-design](../SKILL.md) 的参考。客户提供 VI、品牌手册或设计系统时，依此把它改写成 Agent 可执行的指令，放在 `.agents/skills/<client>-brand/`。本档描述做法，来源范本是 Vercel 的 [design.md](https://vercel.com/design.md)。

## 分工

- **判断**（读者任务、构图、证据、克制）由 `reader-led-design` 负责，品牌 skill 不重写这些规则，只在 SKILL.md 开头指向它。
- **识别**（字标、logo、字体、色彩 token、版型壳、公开 CSS 或元件 API）由品牌 skill 负责。
- 两者冲突时依 `reader-led-design` 的优先序：事实与隐私 > 既有技术栈 > 读者问题与证据 > 品牌识别 > 构图 > 细节。

## 品牌 skill 必备章节

依序写，每节只放品牌手册里有、且会改变产出的内容：

1. **frontmatter**：`name` 用 `<client>-brand`；`description` 写触发分支（哪些页面类型、哪些交付物要套用）。
2. **品牌态度**：用五到七个形容词写品牌语气（例如「精确、冷静、直接、有据、克制」），并写出该品牌拒绝什么。这段是后面所有判断的依据。
3. **资产下载**：字标、logo、图示的稳定网址或仓库路径，标明透明背景、`currentColor` 等使用条件，以及禁止的替代做法（文字代替、内嵌手绘、改色）。
4. **与既有专案整合**：保留宿主框架、路由、档案结构与建置方式；字体与样式表怎么引入；允许的网路资源白名单；禁止另建平行 token 系统。
5. **版型壳**：页首、页尾固定放什么、放哪一侧、允许多少中继资料栏位，附一段精确的 HTML 结构。
6. **视觉系统**：网格栏数、型别角色与字重清单、间距 token 阶层、色彩与表面规则、资料图表色序。只写品牌规定，通用判断交给 `reader-led-design`。
7. **公开 API**：可用的 class 名称与 CSS 变数清单，明示「只用列出的名称，不猜、不造同义词、不读样式表内部」，并规定页面自订样式的命名空间。
8. **无障碍与响应式**：品牌对对比、主题、断点的具体要求。
9. **结语一句话**：用一句话定锚目标，例如「目标是 X 的判断力，不是 X 的装饰」。

## 写法要求

- 指令用肯定句写目标行为；禁止事项只在无法改写为肯定句时保留，并与目标行为并列。
- 每条规则可检查：能用渲染结果判断有没有做到。做不到的删掉。
- 来源品牌手册里的范例、网址、识别码、API 名称保留原值；分析与摘要遵循目标项目的语言规范。
- 写完用 `writing-for-agents` 的标准再修一轮：去重、去 no-op、把只有部分分支需要的内容移到 `references/`。
