# 以读者任务为起点设计

先回答「谁在什么情境打开这一页，要理解或决定什么」，再决定版面；版面由证据的形状决定，不由文件类别决定。目标是**判断力，不是装饰**。

来源：本 skill 从 Vercel 的 [design.md](https://vercel.com/design.md) 提炼可迁移的方法，去掉 Vercel 品牌、`vbg-*` CSS API 与 Geist 字体等专属内容。共用 token、主题与元件来源由专案文件指定；原型与正式版沿用专案的共用来源，不另建平行系统。

## 优先序

需求冲突时依此顺序保护：

1. 来源事实、公式、单位、限定条件、隐私与任务约束。
2. 既有框架、路由、档案结构、专案的共用 token、主题来源与元件惯例。
3. 读者的问题、最强有据答案、关键证据一眼可见。
4. 针对这份素材的构图，而非模型预设版面或固定模板。
5. 响应式、互动与细节，不以削弱层次为代价。

只有在继续做会改变商业含义、法律或安全主张、隐私、公式、单位、母体、期间、客户身分、建议、核准、期限、负责人或行动呼吁时，才集中问一组问题；否则略去未知、如实标示，继续。

## 四个阶段

### 1. 厘清读者任务

看完全部素材再动手。私下确立：

- 谁打开这一页，在什么情境，要决定或理解什么？
- 最强的有据答案是什么？
- 哪些证据让答案可信？
- 哪个取舍、不确定性或限制会改变解读？
- 哪些要留著可查核，但不该主导第一眼？

正规化事实、单位、日期、来源、公式、矛盾、未知与隐私限制。区分**观察、推导、推估、建议、因果**。不替来源发明意图、负责人、急迫性、确定性、期限、核准或未来行为。

依读者需要排序，不依来源顺序。支援两种阅读速度：

- **决策路径**：标题、小标、决定性数值、图说与结论，让人快速掌握论点。用最不专业的具名读者也能复述的白话写。
- **查核路径**：精确表格、假设、方法、限制与来源，保留完整纪录。精确指标名、术语、单位与来源用语留在这里。

简化语言，不简化主张。保留每个会改变意义的限定条件、母体、期间、单位、比较基准与不确定性；「未限速」不等于「一般电脑」，「在量测误差内」不等于「一样快」。具体有据的陈述优于「很小、很大、安全、很快」这类评价性缩写。

每个章节回答一个新的读者问题；重复的合并，仪式性的删除。每个主张只有一个证据家：后面的表格可保留精确查询，但第二个摘要、图表、卡片组或结论不得以同等份量重述同一答案。

冗长帐册放在决策路径之后或原生折叠里。可筛选的大表预设显示中立且与决策相关的子集（全部失败、全部例外、决策点名的每一列），不是「全部」也不是挑选有利的列；标明目前筛选规则，保留查看全部的方法与目前／总计数量。

**完成判据**：上面五个问题都有一句话答案，且决策路径与查核路径的内容已分开。

### 2. 选择构图

第一屏就是论点，不是标题栏加铺陈。可以由主张、证据、比较或工具领头；若读者只看到第一屏，应记得核心关系、决定或工具，而不只是标题或气氛。

动手前先私下说出这类文件「理所当然」的版面，然后拒绝它，除非素材真的需要。素材允许多种结构时，私下比较两个**拓扑、密度、证据位置**都不同的构图假设，选让读者任务最清楚、中介最少的那个；只换配色或元件不算不同假设。

依任务决定开场：

- **明确建议或结论**：答案与其决定性依据并列为主。
- **比较**：把替代方案放在同一视觉基准上，差异用看的，不用从文字重建。
- **趋势或基准**：让关系或例外领头，精确纪录放下面。
- **计算器或互动工具**：操作假设是读者主要任务时，工具本身就是焦点证据，不先放一个静态证明。
- **没有有据结论的简报**：以最强的有据状态、含义、限制或未决问题领头，不发明行动呼吁。

先选几何，再选元件。把素材对应到视觉变数：

| 素材 | 视觉变数 |
| --- | --- |
| 量级或排名 | 同一尺度上的位置或长度 |
| 随时间变化 | 水平顺序与对齐位置 |
| 组成 | 比例 |
| 门槛或区间 | 与边界的距离 |
| 流程或依赖 | 连线与顺序 |
| 定性替代方案 | 对齐的列或刻意对比的栏 |

表格用于精确查询，散文用於单一结论，图表只用在视觉化后更快理解的关系上。有数值不等于要画长条图。

把页面当成一个场，不是元件堆叠。全页一条主线，每个阅读时刻或主要区块一个焦点关系，焦点周围少量支援物件与足够留白。刻意安排卷动节奏：密度与安静交替，但只用一套视觉文法。重复只在项目是真正的同侪时才形成韵律，否则是模板噪音。结尾落在已解决的决定、含义、下一步或未决问题；来源与页尾安静地跟在后面，不让页面停在帐册或警语上。

每个产物要有**一个属于这份素材的证据性组织手法**（比较几何、门槛、序列、客制图解、独特的证据节奏或互动本身），不能原封不动搬到不相干的页面。它澄清主题，不装饰主题。

**瞇眼测试**：一眼看去主张或证据明显、阅读路径稳定。**遮字测试**：文字模糊后，层次仍能传达身分、强调、分组与推进。每个区块权重相同就在写程式前重新设计。

存在感来自承诺，不来自特效。页面太「安全」时，用比例、层次、密度、节奏、断行或证据位置强化一个焦点关系，让支援内容更安静。素材太薄时，改善选择、层次、比较或解释，让缺口诚实留白；绝不用面板、框线、图示、色块、装饰图表或特效补证据缺口。

**完成判据**：能用一句话说出这一页的焦点关系与组织手法，并说明被拒绝的预设版面是什么。

### 3. 套用视觉系统

构图定了再处理字体、间距、色彩、表格、图表、互动、动效与图示。规则见 [references/visual-system.md](references/visual-system.md)；实作时只用专案既有 token 与元件。

**完成判据**：每个间距有唯一拥有者、同侪元素共用同一型别角色、色彩都有非色彩线索配对。

### 4. 私下检视并修正

依产物、本次变更与具体风险，从 [references/self-check.md](references/self-check.md) 的八项与反模式选用相关参考。UI 变更须检查受影响的实际渲染；第一屏、整页与窄萤幕重排依受影响范围选用，双主题仅在产品实际提供且变更涉及主题时验证。

修掉影响最大的系统性缺陷；检查通过后，仅因新改动、失败或未解疑点重复相关检查。这些工作留在内部：交付的是实作本身，不是评分、过程日记或自我批评。

**完成判据**：受影响范围的必要检查完成，没有已知的实质视觉或可用性问题；八项与反模式不作每轮全数通过的固定要求。

## 把客户 VI 规范写成专案 skill

客户提供 VI 或品牌规范时，依 [references/brand-skill-template.md](references/brand-skill-template.md) 整理成 `.agents/skills/<client>-brand/`，让后续会话产出一致。本 skill 负责判断，品牌 skill 负责识别；两者分开维护。
