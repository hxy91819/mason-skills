# PPT Visual Review

流程类 Skill，仅在用户显式调用 `$ppt-visual-review` 时运行。审查目标是观众能否看懂每页要传递的判断及其证据；真实画面是判定依据，几何测量是线索。

## 1. 固定输入与权限

记录 deck 路径、版本/哈希、实际页数、受众、观看方式与投影视口。引用的图片、比较页面也记版本；旧线程已加载的技能与旧截图不能冒充新版评测。区分用户已指出的问题、本轮独立发现和旧报告待复核项。

按用户请求选模式：明确“只审查、给建议、不改源文件”时**只读审查**，只写报告与截图；要求修复或仅调用本技能且未限制权限时，延续**布局修复**，可直接改版式，不必逐条审批。两种模式都完整看图。

布局修复只改样式与现有元素定位。文案、数字、事实口径、内容结构、页数、素材选择的变化交给制作方：写明哪页哪个区域、具体替换文案/拆页安排/所需画面与验收条件，保持待处理，不擅改、不伪造 after。用户已限制只读时不进入修复分支。

从目标自身读取画布、页边距、字号层级、间隔档位与重复布局的出处。若各页承担不同阅读任务，分别记录合理的布局；跨页一致性服务于阅读节奏，不要求每页同样密度、对称或填满。

完成标准：输入版本、模式、实际页数、投影规格和现有版面契约可追溯。

## 2. 采集完整画面

```bash
node scripts/measure-deck.js --file <deck.html> --out <临时目录> --label before --shot
```

使用脚本的 `--help` 查选择器、浏览器依赖与阈值。阅读 [scripts/measure-deck.js](scripts/measure-deck.js) 头部的视觉盒口径再解释数值。产物包含每页几何、flags、plain 与 ruler 图。

逐页核对截图对应的页、当前版本和真实内容，等待字体与图片稳定。脚本会激活页并尝试缩放到原画布，这适合测量，**不能证明实际演示的导航和投影表现**：还要在实际演示视口打开原页面，用原控件翻页并截图。图片未加载、空白、错误页、切到错误页都算采集失败。选择器数量与有意义的画面数分别核对。

脚本 flags 除几何（节奏/对称/档位/留白/跨页）外，还覆盖常见 HTML PPT 陷阱：文本箭头与相邻文字带错位（connector）、内容被裁切或页根溢出（overflow）、图片拉伸变形/过度放大/加载失败（image）、文本被覆盖（occlusion）、纯色背景下的 WCAG 对比度（contrast）、自定义字体未加载（font）。flags 是线索不是结论：每个 flag 都要打开对应截图裁决，未报 flag 的区域照样要过一遍下节清单。

建立单轮逐页覆盖记录：页 id、输入版本、截图路径/视口、实际看过的画面与局部、具体观察、交互步骤和结果/不适用理由、缺口。先列全页，再填已检查项；生成文件、打开 HTML、返回图片路径或 flags=0 不算看图。截图不可用的页保留在总数中，记覆盖不足。

## 3. 逐页看图并实际操作

使用可看图的工具打开**每一页 plain 和 ruler**，在投影尺度先判断整页，再放大核对关键细节；放大可辨不代表投影可读。每页都回答下列问题，未报 flag 的区域也要检查：

- **投影可读性**：观众完成本页判断所需的原文、数字、图例、运行结果是否在正常演示尺度可辨？截图中的小字、低对比、裁切和遮挡同样检查。关键信息需要放大/重排时列为问题，讲者口播不能替代承诺由画面提供的证据。
- **视觉重心与留白**：第一眼看哪里，标题、主体、证据之间如何移动视线？大块空白是否承担标题停顿、对照、构图或层级用途，还是主体挤在顶部且关键证据缩得太小？指出具体影响再定级；统一居中、填满或统一间距都不是默认修法。
- **证据可见性与图文对应**：标题的判断能否从画面定位到证据？截图内容、图注、突出数字、时间/状态是否对应同一对象和版本？图片“存在”不等于证据有效。关键证据缺失、选错或只能证明工具界面存在时，给制作方具体补图/改稿建议。
- **比较是否成立**：前后是否指向同一对象、数据范围、信息任务与可解释的时间变化？逐一找到共同锚点和变化，说明画面能支持什么结论。裁剪坐标相同不足以证明可比；重排允许内容移动，但不能把不相干局部当作前后改善。
- **版式节奏**：结合阅读任务核对间隔、页边距、对齐、跨页同角色位置、装饰与正文的关系。几像素错位或不同密度只在造成可见影响时成立。

演示包含展开、导航、并排或拖动比较时，在**实际页面/嵌入位置**操作并看操作后的图；链接或控件存在不算完成。比较控件检查左右极值、中点、图像锚点、左右标签、并排往返和 resize（包括并排隐藏滑块时 resize）。受权限限制无法操作时写明范围；不为制造状态提交表单或触发外部写操作。

除上述五问外，逐页另查常见 HTML PPT 陷阱（无 flag 也要看）：

- **连接与行内对齐**：文本箭头、连接线、时间线圆点与相邻文字的视觉中心是否对齐（注释行撑高行时居中元素会下沉）；大小字号 inline 混排基线；badge/icon 与文字。
- **截断与溢出**：nowrap/ellipsis/滚动容器是否裁掉文字；页根是否溢出（演示时出现滚动条或被静默裁切）。
- **图片与资产**：是否拉伸变形、位图过度放大发虚、加载失败、被图注/叠层遮住关键信息。
- **遮挡与对比度**：文字是否被兄弟元素盖住；低对比小字、强调色是否低于可读下限（红字浅底常见）。

逐页看图可派发给 subagent，且任务重时按方向拆分多个 subagent 并行（只读，可连续派发；用户配置了 BB 派发时可用 `$bb-model-routing`）。方向划分建议：**A 观众理解**（投影可读性、证据可见性、图文对应、比较是否成立）、**B 版式几何**（节奏、对齐、连接符、留白、跨页一致）、**C 资产与交互**（截断溢出、图片质量、遮挡、对比度、导航与比较控件实操）。每个 subagent 领取产物目录、本节对应检查项与页面清单，返回逐页观察与 findings 草案（含红框 box 坐标、短标签与定级建议）。主 agent 必须亲自复核将进入报告的每条 finding：打开它引用的截图确认证据与定级，评估意见（采纳/修正/拒绝 + 理由）以 finding id 记入本轮记录；多方向命中同一问题时合并成一条 finding 并注明命中方向。未经复核的草案不得写入报告，subagent 转述不能替代主 agent 看图。派发元数据（provider/模型/推理级别）由派发机制决定，不写入审查结论。

完成标准：每页有图上可定位的观察，关键位图细节已核对，交互有实际步骤与结果。无法辨认的内容记录为不可辨认；由此影响本页判断时形成 finding，不能猜原文。

## 4. 定级与处理

按观众的任务定级：**阻断**是无法完成主要判断、关键证据不可见/误导或必要交互失效；**应改**是可读性、重心或对应关系明显增加理解负担；**可选**是无需修复也能正确理解的细节。slack 数值或列底错位不自动对应严重度。

每条 finding 写页与区域、截图证据、读者影响、具体建议、权限范围及状态。产出规格（供报告渲染）：`box` 为红框在截图上的像素坐标 `[x,y,w,h]`（坐标空间 = `img` 指向的截图，缺省该页 before 截图；也可用 `boxPct` 百分比），红框必须圈住截图上可验证的真实问题区域；`label` 为框旁短标签（≤16 字，如「空带 160px」）；`short` 为一句话问题说明；大段分析写 `why`，不进红框文字。保留项写出画面中的具体用途；判不准的项记待确认，不为凑数升级，也不按“设计意图”一概豁免。制作说明若妨碍视觉任务可指出并给改稿建议，不能据此越权改文案。

只读模式在报告中保留现状与建议。布局修复优先修改共享样式/容器策略，逐页确认不会损害不同内容的阅读任务；内容或素材变化超出权限时输出可执行交接建议。实际修复、建议待执行、明确保留分别记录，建议文本不能充当修复结果。修复模式按评估后的 findings 逐条修改，复验后为每条 fixed finding 提供 `afterImg`（与改前同视口同尺寸的整页截图），报告为其渲染前后对照；无真实 after 不出对照图。

## 5. 复验与报告

布局修复后重跑测量并逐页复看 after，包括未直接改动但受共享样式影响的页；复测实际演示交互，运行被审项目现有相关门禁。flags 只对照变化，每条残留线索有视觉裁决；flags 清零不等于验收完成。只读审查不生成虚构的改后状态。

```bash
python3 scripts/build-report.py --data findings.json --check
python3 scripts/build-report.py --data findings.json --out <报告.html>
```

字段与状态规则见 [scripts/build-report.py](scripts/build-report.py) 头部说明。`pages[].review` 写真实观察而非布尔“已看”；`pageCount` 写实际总页数；`limits` 记录缺图、不可辨认的关键证据、未操作状态等。缺 after 时只展示现状；两张图都真实存在才提供前后对比，标尺图也不互相替代。

报告为单文件 HTML，所有区块**默认折叠**并配「全部展开/收起」，方便逐块审查。主结构是问题卡：上半部是红框标注截图（框选问题位置 + 短标签 + 一句话说明，不用大段文字），下半部是该问题的改前/改后对照滑块图（一个图框内竖条切换，仅当两张图都真实存在；无 after 只显示红框现状，不伪造对照）；完整分析与处理记录在卡内二级折叠。「逐页覆盖记录」每页一卡，保留页级 before/after 对照与标尺图。长分析仍写入 why，红框文字只写短标签。

打开生成的报告实际验证：默认折叠状态与展开/收起接线、红框位置与标签、滑块拖动/极值/中点、并排/标尺切换及 resize。报告缩图可能损失细节，审查仍以原截图为依据。

状态以证据和未处理项为准：覆盖缺口为 `incomplete`；仍有待制作方处理/待确认项为 `reviewed`；只有全页及适用交互已核对、无待修项才可 `clean`；布局修复经同等复验才可 `fixed`。无发现也出报告，不把未检查写成无问题。浏览器模拟投影与真人现场验收分别陈述。

## 单轮回看与限制

`build-report.py --data <记录.json> --check` 只读汇总已登记的覆盖页数/实际总页数、未处理发现/发现总数、状态及缺口。聚合只校验记录一致性，不能代替实际看图或确认语义判断质量。报告和截图留在用户指定产物目录或系统临时目录，不放技能源码仓库。

BB 宿主下记录 thread id，用 `bb thread log <id>`、`bb thread output <id>` 回看真实工具调用和结果；执行身份以宿主记录为准。复用这些持久化事实与单轮记录，不建全局账本。当前缺口：无跨轮质量统计、接受率 rollup 或自动裁决回写；制作方的采纳/拒绝理由以 finding id 写入本轮记录，不能从未回复推断接受。
