# PPT Visual Review

流程类 Skill，仅在用户显式调用 `$ppt-visual-review` 时运行。审查目标是观众能否看懂每页要传递的判断及其证据；真实画面是判定依据，几何测量是线索。

## 0. 审查与修复分工

默认采用「独立审查 → 主 Agent 修复 → 审查者复验」闭环。这里的独立指审查任务与修复职责分离，不承诺不同模型。主 Agent 负责固定输入、派发、判断意见是否在范围内、修改源文件和运行项目验证；审查 Agent 负责截图、逐页看图、实际交互、定级、复验及生成最终报告。主 Agent 不需要重复全量视觉审查或逐条打开截图，证据有歧义时让审查者补充，必要时定点查看。

默认启动一个可看图、可操作浏览器的 subagent，传入下方交接材料，使用独立任务上下文；用户选择 BB 或宿主无可用 subagent 时，通过宿主按名称加载 `$bb-model-routing`，派发一个审查线程。模型与推理级别沿用派发机制和用户配置。能力或并发额度不可用时记录缺口；未实际启动审查者不得把主 Agent 自审宣称为独立审查。只需一个审查者覆盖全 deck；只有用户要求或页数确实需要拆分时才按页面分工并合并覆盖记录。

交接材料包含：本 Skill 的解析后绝对路径、角色 `reviewer`、deck 及依赖资产路径/URL、输入版本、全部页清单、受众与视口、用户原始要求、只读或修复模式、布局权限、独立产物目录。审查者阅读本 Skill 后直接执行第 1–3 节和第 4 节的定级记录，不再次派发，也不修改 deck；第 4 节的源文件修复由主 Agent 执行。使用本 Skill 根目录下的脚本，不能假设当前工作目录就是 Skill 目录。

审查者首轮返回 `findings.json` 路径、覆盖/缺口摘要及待修 finding ID；数据包含本节所列审查证据；进入 HTML 输出时按 `$review-html-report` 的数据契约填写，包含逐页真实观察、问题截图、坐标、影响、建议与验收条件。主 Agent 逐条记录采纳/修正/拒绝及理由：可修的直接修，范围外项保持待处理；拒绝项用 `resolution=kept` 和 `resolutionReason` 留痕。用户明确要求只读时，审查者直接生成报告，不进入修复。

修复后主 Agent 将改动摘要、对应 ID、最新版本及验证结果交回同一审查者；线程不能续办时，将原始记录和产物交给新审查者。审查者执行第 5 节，确认问题是否解决及有无回归；未通过的返回主 Agent 继续修复。主 Agent 提交的修复说明不等于视觉复验通过，只有审查者看过真实 after 才将对应项标为 `fixed`。保留首次 before、每轮版本与记录，最终 after 使用最新复验版本；中途发现的问题使用其首次出现时的真实截图，不把已修问题从最终清单删除。

没有范围内待修问题且覆盖完整时结束；剩余项依赖缺失的内容/素材或存在工具、证据阻塞时，输出待处理项与缺口，不虚报完成。相同问题再次复验仍无改善时先由审查者补充定位证据与可验证修复方向，避免机械重复改动。收尾报告及其浏览器实测由审查者完成，主 Agent 交付链接和未解决事项。

## 1. 固定输入与权限

记录 deck 路径、版本/哈希、实际页数、受众、观看方式与投影视口。引用的图片、比较页面也记版本；旧线程已加载的技能与旧截图不能冒充新版评测。区分用户已指出的问题、本轮独立发现和旧报告待复核项。

按用户请求选模式：明确“只审查、给建议、不改源文件”时**只读审查**，只写报告与截图；要求修复或仅调用本技能且未限制权限时，进入**直接修复**，在本次审查范围内修改版式及有证据支持的内容问题，不必询问是否修复或逐条审批。两种模式都完整看图。

直接修复样式、定位、制作说明残留及可由现有证据确定的文案、结构和素材问题；同步相关页面。保留真实事实与用户原意，缺失的数字、事实或素材不能编造：仅将依赖缺失输入的条目留作待处理，继续完成其余修复。用户明确限制只读时不修改源文件。

从目标自身读取画布、页边距、字号层级、间隔档位与重复布局的出处。若各页承担不同阅读任务，分别记录合理的布局；跨页一致性服务于阅读节奏，不要求每页同样密度、对称或填满。

完成标准：输入版本、模式、实际页数、投影规格和现有版面契约可追溯。

## 2. 采集完整画面

```bash
node scripts/measure-deck.js --file <deck.html> --out <临时目录> --label before --shot
```

使用脚本的 `--help` 查选择器、浏览器依赖与阈值。阅读 [scripts/measure-deck.js](scripts/measure-deck.js) 头部的视觉盒口径再解释数值。产物包含每页几何、flags、plain 与 ruler 图。

逐页核对截图对应的页、当前版本和真实内容，等待字体与图片稳定。脚本会激活页并尝试缩放到原画布，这适合测量，**不能证明实际演示的导航和投影表现**：还要在实际演示视口打开原页面，用原控件翻页并截图。图片未加载、空白、错误页、切到错误页都算采集失败。选择器数量与有意义的画面数分别核对。

脚本 flags 除几何（节奏/对称/档位/留白/跨页）外，还覆盖常见 HTML PPT 陷阱：文本箭头与相邻文字带错位（connector）、内容被裁切或页根溢出（overflow）、图片拉伸变形/过度放大/加载失败（image）、文本被覆盖（occlusion）、纯色背景下的 WCAG 对比度（contrast）、自定义字体未加载（font）。flags 是线索不是结论：每个 flag 都要打开对应截图裁决，未报 flag 的区域照样要过一遍下节清单。

建立简要检查记录：共享输入版本和视口，每页只记页 id、一句结论及发现 ID；截图留在本地产物目录，交互步骤按共同流程汇总，异常单列。先列全页，再填已检查项；生成文件、打开 HTML、返回图片路径或 flags=0 不算看图。截图不可用的页保留在总数中，记覆盖不足。

## 3. 逐页看图并实际操作

使用可看图的工具打开**每一页 plain 和 ruler**，在投影尺度先判断整页，再放大核对关键细节；放大可辨不代表投影可读。每页都回答下列问题，未报 flag 的区域也要检查：

- **投影可读性**：观众完成本页判断所需的原文、数字、图例、运行结果是否在正常演示尺度可辨？截图中的小字、低对比、裁切和遮挡同样检查。关键信息需要放大/重排时列为问题，讲者口播不能替代承诺由画面提供的证据。
- **视觉重心与留白**：第一眼看哪里，标题、主体、证据之间如何移动视线？大块空白是否承担标题停顿、对照、构图或层级用途，还是主体挤在顶部且关键证据缩得太小？指出具体影响再定级；统一居中、填满或统一间距都不是默认修法。
- **证据可见性与图文对应**：标题的判断能否从画面定位到证据？截图内容、图注、突出数字、时间/状态是否对应同一对象和版本？图片“存在”不等于证据有效。关键证据缺失、选错或只能证明工具界面存在时，给制作方具体补图/改稿建议。
- **比较是否成立**：前后是否指向同一对象、数据范围、信息任务与可解释的时间变化？逐一找到共同锚点和变化，说明画面能支持什么结论。裁剪坐标相同不足以证明可比；重排允许内容移动，但不能把不相干局部当作前后改善。
- **版式节奏**：结合阅读任务核对间隔、页边距、对齐、跨页同角色位置、装饰与正文的关系。几像素错位或不同密度只在造成可见影响时成立。

演示包含展开、导航、并排或拖动比较时，在**实际页面/嵌入位置**操作并看操作后的图；链接或控件存在不算完成。比较控件检查左右极值、中点、图像锚点、左右标签、并排往返和 resize（包括并排隐藏滑块时 resize）。受权限限制无法操作时写明范围；不为制造状态提交表单或触发外部写操作。

除上述五问外，逐页另查常见 HTML PPT 陷阱（无 flag 也要看）：

- **连接与行内对齐**：文本箭头、连接线、时间线圆点与相邻文字的视觉中心是否对齐（注释行撑高行时居中元素会下沉）；大小字号 inline 混排基线；badge/icon 与文字。
- **截断与溢出**：nowrap/ellipsis/滚动容器是否裁掉文字；页根是否溢出（演示时出现滚动条或被静默裁切）。
- **图片与资产**：是否拉伸变形、位图过度放大发虚、加载失败、被图注/叠层遮住关键信息。
- **遮挡与对比度**：文字是否被兄弟元素盖住；低对比小字、强调色是否低于可读下限（红字浅底常见）。

本节由审查 Agent 执行并保存逐页观察。多个审查任务命中同一问题时按 finding ID 合并证据；主 Agent 消费结构化意见进行修复，视觉裁决与复验由审查者负责。

完成标准：每页有图上可定位的观察，关键位图细节已核对，交互有实际步骤与结果。无法辨认的内容记录为不可辨认；由此影响本页判断时形成 finding，不能猜原文。

## 4. 定级与处理

按观众的任务定级：**阻断**是无法完成主要判断、关键证据不可见/误导或必要交互失效；**应改**是可读性、重心或对应关系明显增加理解负担；**可选**是无需修复也能正确理解的细节。slack 数值或列底错位不自动对应严重度。

每条 finding 标记 `category`：`visual` 为可读性、布局、对齐、遮挡、溢出、图文位置对应与交互；`content` 为论据充分性、统计口径、事实完整性、比较逻辑及素材能否支撑结论。按问题性质判断，例如“证据文字太小”属于视觉，“百分比缺样本口径”属于内容。两类检查和可执行修复均保留；缺少事实依据或素材的条目说明所缺输入。

每条 finding 写页与区域、截图证据、读者影响、具体建议、权限范围及状态。产出规格（供报告渲染）：`box` 为红框在截图上的像素坐标 `[x,y,w,h]`（坐标空间 = `img` 指向的截图，缺省该页 before 截图；也可用 `boxPct` 百分比），红框必须圈住截图上可验证的真实问题区域；`label` 为框旁短标签（≤16 字，如「空带 160px」）；`short` 为一句话问题说明；大段分析写 `why`，不进红框文字。保留项写出画面中的具体用途；判不准的项记待确认，不为凑数升级，也不按“设计意图”一概豁免。制作说明若妨碍视觉任务，直接删除、移位或改写，并保留必要事实限定。

只读模式在报告中保留现状与建议。修复优先修改共享样式/容器策略，逐页确认不会损害不同内容的阅读任务；内容或素材缺少依据时输出具体待处理说明。实际修复、建议待执行、明确保留分别记录，建议文本不能充当修复结果。修复模式按评估后的 findings 逐条修改，复验后为每条 fixed finding 提供 `afterImg`（与改前同视口同尺寸的整页截图），报告为其渲染前后对照；无真实 after 不出对照图。

## 5. 复验与报告

修复后重跑测量并逐页复看 after，包括未直接改动但受共享样式影响的页；复测实际演示交互，运行被审项目现有相关门禁。flags 只对照变化，每条残留线索有视觉裁决；flags 清零不等于验收完成。只读审查不生成虚构的改后状态。

默认在修复和复验后通过宿主按名称加载 `$review-html-report`，自动生成并交付 HTML 报告，无需询问用户是否修复或是否需要 HTML。报告按“视觉与交互问题”“内容与证据建议”分组，每个问题与对应修复及真实前后对照放在一起。保留本地 `findings.json` 和截图，回复给出报告链接、简要结果及剩余待处理项。

用户明确要求只读时只审查，仍默认交付 HTML；明确要求只要文字或不要 HTML 时改为 Markdown。后续要求其他格式可复用本轮记录，并注明对应版本。

共享技能维护数据契约、HTML 样式、图片嵌入、反馈和浏览器展示验证。本技能继续维护真实看图与修复复验标准；`pages[].review` 记录简要真实结论，`pageCount` 写实际总页数，`limits` 记录缺图、不可辨认的关键证据及未操作状态。过程记录保留在 JSON。

调用共享技能时设置报告标题为「PPT 版式视觉验收」，使用 visual 证据模式；默认只嵌入已修项必要图片、不展开覆盖过程。保留现有按视觉/内容分组、问题与修复同卡、未修改项不出修复对照的展示。审查者按共享技能契约完成 HTML 渲染及展示验证，返回链接。共享技能由宿主解析安装位置，不从本技能相邻目录或固定 user scope 调用其脚本。

状态以证据和未处理项为准：覆盖缺口为 `incomplete`；仍有待制作方处理/待确认项为 `reviewed`；只有全页及适用交互已核对、无待修项才可 `clean`；修复经同等复验才可 `fixed`。无发现也出报告，不把未检查写成无问题。浏览器模拟投影与真人现场验收分别陈述。

## 单轮回看与限制

需要结构化校验时由宿主加载 `$review-html-report`，运行它的 `scripts/build-report.py --data <记录.json> --check`，只读汇总已登记的覆盖页数/实际总页数、未处理发现/发现总数、状态及缺口。聚合只校验记录一致性，不能代替实际看图或确认语义判断质量。报告和截图留在用户指定产物目录或系统临时目录，不放技能源码仓库。

每轮记录审查任务/线程 ID、输入版本和产物路径，主 Agent 的处理理由以 finding ID 写入本轮记录。subagent 使用宿主任务记录回看；BB 宿主下记录 thread id，用 `bb thread log <id>`、`bb thread output <id>` 回看真实工具调用和结果；执行身份以宿主记录为准。复用这些持久化事实与单轮记录，不建全局账本。当前缺口：无跨轮质量统计、接受率 rollup 或自动裁决回写；制作方的采纳/拒绝理由以 finding id 写入本轮记录，不能从未回复推断接受。
