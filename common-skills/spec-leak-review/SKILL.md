# Spec Leak Review

只读审查，不修改被审文件。先按对象选择模式：

- **文本模式**：目标是任意可读文本（包括 `SKILL.md`、`AGENTS.md`、`CLAUDE.md`、`agents/openai.yaml`、提示词、设计稿、配置、日志片段等），或用户明确要求审查文档内容。以文件或用户提供的原文为证据，不启动浏览器、不截图、不做视觉定级。
- **网站模式**：目标是网站或网页应用，或用户明确要求检查网站页面的真实渲染。保留截图采集、bbox 定位和视觉复核；截图只服务于网站渲染证据。

混合输入按文件分别采集证据：文本文件走文本模式，网站页面走网站模式。报告开头写明模式和覆盖范围。

## 1. 确定受众与决策

先回答三件事并写进报告开头：谁会阅读或打开目标；带着什么疑问来；看完之后要做出什么决定或动作。文本模式中的“受众”可以是执行该文档的 agent、维护 Skill 的作者或文档读者；网站模式中的“受众”是页面用户。

受众决定一切判定——同一句“清单摘要 975d85…”对终端用户是噪音，对值班运维是工作对象。无法从用户输入、目标文件、网站上下文或代码判断受众时，先问用户，不要假设后展开审查。

完成标准：受众和“看完要做的决定”各能用一句话说清，且后续每条 finding 都能挂回其中一句。

## 2. 建立证据清单

### 文本模式

逐个读取用户指定的文本；没有指定文件时，只扫描任务范围内的文本，不把二进制或依赖目录当成证据。保留原文、文件路径和行号（必要时给出段落或字符范围），并记录文件用途、预期读者和是否由配置/模板生成。多文件交叉引用时以实际引用链为准，不凭目录名推断。

重点标出这些**提示词残留**：面向模型的会话开场、角色扮演、一次性用户请求、对当前对话的指代、隐藏推理或“请先……再……”的临时编排、把宿主/调用方式复述进正文的元说明，以及与文档任务无关的用户背景。提示词语气本身不是问题：Skill 的操作步骤、约束和安全门槛只要服务于预期读者，就属于正文。

完成标准：每个被审文件都有用途、读者、覆盖行数和证据位置；每条 finding 都能回指原文行号或明确标注为用户提供的片段。

### 网站模式

双轨采集，两轨都有时交叉核对。

**截图轨**：界面能跑起来时，用 [`scripts/capture-surface.js`](scripts/capture-surface.js) 采集每个网站页面，得到全页截图和带文档坐标 bbox 的可见文本清单。它把 placeholder、`title`、`aria-label` 一并收进来，并标出元素是否藏在 `<details>` 里、字号多大——这些是视觉复核的依据。脚本落地在浏览器错误页时以非零码退出，此时截图不能当作被审页面的证据。

拿不到浏览器或页面跑不起来时，用用户提供的网站截图逐区域盘点：标题、副标题、卡片标题、说明文字、字段名、字段值、状态标签、按钮、空态占位、时间戳。看到的每一块可见文字都进清单，包括看起来无害的；坐标从图上量出来。辨认不出的文字标注为不可辨认，不猜测内容。

**代码轨**：用截图里的文案原文在仓库检索定位组件与 i18n 条目，比按目录猜更可靠；每条给出 `file:line`。截图未出现的错误态、空态、tooltip、loading 等分支文案一并纳入清单。文案有配置或环境变量覆盖机制时，确认线上生效值，不拿源码默认值当结论。

截图里有而代码里检索不到的，标注来源为运行时数据或后端返回。部分区域因鉴权、外部网关或无法构造触发条件而采集不到时，如实记录范围和原因，不用源码推断冒充渲染结果。

完成标准：清单条目数不少于截图中可见文字块数；每条要么有 `file:line`、运行时数据或不可辨认说明，要么（网站渲染面条目）带 bbox。

## 3. 逐条判定

对清单每一条先归类，再给结论。以下类别适用于两种模式；“网站”措辞在文本模式替换为“该文档的预期读者”。

1. **否定式免责**——告诉读者“本页/本文不做什么”。信号词：不会、不再、不读取、不显示、不同步、仅、只。只有在回答隐私、计费、数据删除、权限等真实顾虑时才保留。
2. **实现策略外泄**——把取数、路由、优先级、回退、同步规则当成面向读者的说明；在 Skill 或工程文档中，若它是执行所需的规则则保留，否则视为重复或泄漏。
3. **验收标准当文案**——把“用于核对/用于确认 X 与 Y 是否一致”等测试目的写成面向读者的介绍。
4. **元文案自述**——“这里展示…”、“本页用于…”或解释文档/页面为何存在；职责已经由标题、结构或元数据表达时，通常删除或改写。
5. **内部代号与技术标识**——服务名、仓库名、组件名、hash、Release ID；受众不认识，或认识但无法据此采取动作。
6. **无动作信息**——只呈现状态不给下一步；异常时读者不知道能做什么；标识符不可复制。
7. **占位与调试残留**——`—`、`暂无`、示例值、TODO、临时日志或调试输出随版本发布。
8. **提示词残留（文本模式重点）**——用户请求的口吻、会话上下文、模型角色/系统提示复述、一次性任务背景、隐藏推理或仅为引导 agent 当次作答的编排。判断依据是：删掉后是否损害文档作为长期规范/参考的可执行性；不损害则删除或改写。正常的规范性祈使句、步骤和安全门槛不因“像提示词”而标记。

每条结论四选一：**保留 / 改写 / 降级 / 删除**。降级指移出主要阅读路径——网站可收进 tooltip、帮助文档、日志或内部模式；文本可移到维护者注释、附录或变更记录。

防过度标记：受众本身是运维或开发时，技术标识可能就是工作对象；否定式陈述若回答受众第一次会产生的真实顾虑则可保留；对外求助所需且可复制的标识符也可保留。判不准时按保留处理并列入待确认清单，不为凑数量升级成问题。

每条“改写”必须写出可直接替换的完整目标文案。目标文案只描述读者关心的事实和可采取的动作，用陈述句表达职责，不用否定句表达“不做什么”。文本模式的改写要保持原文件格式、语气和语义边界，不把实现规则改写成面向终端用户的宣传语。

完成标准：每条 finding 都有类别、结论、受众依据、原文位置和完整建议；保留项与待确认项说明了理由。

## 4. 复核与定级

### 文本模式

沿原文上下文复读每条 finding，确认它确实是提示词/需求外泄，而不是执行该文档所需的规范。复核重点是语义必要性、重复的元说明、读者是否会误把内部指令当成内容；不调用截图工具，也不推断字号、首屏或视觉层级。按三档定级：

- **阻断**：会让 agent 或文档读者执行错误任务、误解权限边界，或把敏感的用户/系统提示词带入长期文件。
- **应改**：纯元说明、一次性上下文、实现细节重复或无动作信息，增加阅读负担但不改变核心执行结果。
- **可选**：轻微措辞、层级或重复优化。

### 网站模式

判定完回到真实截图，逐条把被判定的原文用 [`scripts/annotate-shot.py`](scripts/annotate-shot.py) 圈出来。截图里找不到的条目退回第 3 步重新归类，不带着“应该在那儿”的假设进报告。排版会改变结论：首屏主视觉或过大的字号升一级；已收在 `<details>`、tooltip 且入口标注内部用途的降一级或保留；字号层级不匹配但文案本身没问题时，单独记为层级问题。采集不到或只出现在构造不出的分支里的条目不做视觉复核，在报告逐条写明原因。

网站模式完成标准：每条来自渲染面的 finding 都有一张能看清原文的标注截图；其余条目写明未截图原因。文本模式完成标准：每条 finding 都有可复核的原文位置和上下文理由，不产生截图要求。

## 5. 输出报告

以 [assets/report-template.html](assets/report-template.html) 为骨架渲染单文件 HTML，默认写到系统临时目录并在回复中给出绝对路径；用户指定路径时写到指定位置。报告标题、摘要和证据区明确写“文本模式”或“网站模式”。

网站模式的截图先在报告里写占位符：finding 的标注图用 `__EMBED_<finding id>__`，全景图用 `__EMBED_overview:<截图名>__`；再用 `annotate-shot.py --inject <报告路径>` 就地替换成 base64 data URI。它会报告替换数量与内嵌图片数；有缺图或残留占位符时以非零码退出。文本模式删除截图占位符、全景图和视觉复核段，改为列出审查文件、行号和覆盖范围，不运行注入脚本。

报告必须包含：

- 模式、受众与决策结论，作为全篇判定依据。
- 文本模式的文件清单、用途、覆盖行数与未覆盖原因；网站模式的每个页面全景截图、采集不到的范围和原因。
- 按严重度分组的 findings，每条含原文、类型、为什么该受众不需要、结论、建议文案和位置。网站渲染面 finding 还要有圈出原文的标注截图；文本 finding 不放截图，写明原文行号与上下文。
- 原文与建议文案的对照、待确认清单，以及改写后的整页或整篇文案全文。

无问题时同样输出报告，状态标为 clean。

## 不变量

- 只读：不修改被审仓库的任何文件，只写报告与截图产物。
- 不发起外部写操作（评论、工单、消息、推送）。网站采集不要为了构造状态去触发失败登录、提交表单或改配置。
- 网站截图必须是真实渲染产物；拿不到就记为覆盖范围限制，不用示意图、手绘或源码推断代替。文本模式以读取到的原文为唯一证据，不补全缺失内容。
- 结论只基于实际读到的文案、文本和代码；不可辨认或未定位的内容如实标注，不补全成看似合理的文本。
