# Spec Leak Review

流程类 Skill，仅在用户显式调用 `$spec-leak-review` 时运行。只读审查，不修改被审文件。先按对象的用途选择模式：

- **文本模式**：长期规范、提示词、配置、日志、纯文本讲者备注等。以文件或用户提供的原文为证据，不启动浏览器、不截图、不做视觉定级。
- **视觉模式**：网站、网页应用、PPT/幻灯片（包括 HTML、PDF 或图片形式）及其中的比较页面。必须逐页真实看图，不能因为 HTML 可读源码而降为文本模式。用目标格式的渲染工具获取画面；用户提供的截图也可作为已覆盖部分的证据。

混合输入分别记录，例如幻灯片走视觉模式、独立备注走文本模式。报告开头写明模式、输入版本/哈希、实际页数/界面状态、受众和覆盖范围。视觉采集失败时保持视觉模式并记录缺口。

## 1. 确定受众与决策

先回答三件事并写进报告开头：谁会阅读或打开目标；带着什么疑问来；看完之后要做出什么决定或动作。文本模式中的“受众”可以是执行该文档的 agent、维护 Skill 的作者或文档读者；视觉模式中的“受众”是页面用户或演讲观众。

受众决定一切判定——同一句“清单摘要 975d85…”对终端用户是噪音，对值班运维是工作对象。无法从用户输入、目标文件、网站上下文或代码判断受众时，先问用户，不要假设后展开审查。

完成标准：受众和“看完要做的决定”各能用一句话说清，且后续每条 finding 都能挂回其中一句。

## 2. 建立证据清单

### 文本模式

逐个读取用户指定的文本；没有指定文件时，只扫描任务范围内的文本，不把二进制或依赖目录当成证据。保留原文、文件路径和行号（必要时给出段落或字符范围），并记录文件用途、预期读者和是否由配置/模板生成。多文件交叉引用时以实际引用链为准，不凭目录名推断。

重点标出这些**提示词残留**：面向模型的会话开场、角色扮演、一次性用户请求、对当前对话的指代、隐藏推理或“请先……再……”的临时编排、把宿主/调用方式复述进正文的元说明，以及与文档任务无关的用户背景。提示词语气本身不是问题：Skill 的操作步骤、约束和安全门槛只要服务于预期读者，就属于正文。

完成标准：每个被审文件都有用途、读者、覆盖行数和证据位置；每条 finding 都能回指原文行号或明确标注为用户提供的片段。

### 视觉模式

双轨采集，两轨都有时交叉核对。

**截图轨**：用 [`scripts/capture-surface.js`](scripts/capture-surface.js) 或目标格式渲染器采集每个页面/幻灯片。脚本生成真实截图、文档坐标 bbox 的 DOM 文本清单及 `surfaces` 绘制面清单；后者包括图片、canvas、SVG、背景图、嵌入页等需单独看图的区域，不含位图文字识别。`title`/`aria-label` 属于辅助属性，不能直接当作当前画面已显示的文案。脚本非零退出、错误页、失败图片都要记录缺口；采集成功也不代表完成审查。

**真正打开每一张截图看图**，按区域盘点标题、副标题、说明、卡片、字段、状态、按钮及位图内文。`surfaces` 是补充盘点入口；图中存在而清单未捕获的区域（如 iframe 内部、伪元素或复杂合成）手工补入。对每个承载文字/证据的位图记录截图/素材、页与 bbox、实际读到的原文及用途；alt、OCR 和 DOM 清单只作线索，须回图核对。不可辨认处记录范围与原因，不凭上下文补写。

在实际投影视口看整页，再看重要局部。逐页记录已打开的图、视口、具体观察、位图覆盖及缺口；关键制作说明或证据不能因小字而免审。拿不到浏览器时可以使用用户已有截图，未覆盖的页/状态仍保留在总数中。

**代码轨**：用截图里的文案原文在仓库检索定位组件与 i18n 条目，比按目录猜更可靠；每条给出 `file:line`。截图未出现的错误态、空态、tooltip、loading 等分支文案一并纳入清单。文案有配置或环境变量覆盖机制时，确认线上生效值，不拿源码默认值当结论。

截图里有而代码里检索不到的，标注来源为运行时数据或后端返回。部分区域因鉴权、外部网关或无法构造触发条件而采集不到时，如实记录范围和原因，不用源码推断冒充渲染结果。

对展开、tooltip、幻灯片导航、比较切换等无写入交互，实际操作后再看图并记录步骤、状态与结果；嵌入画面的真实内容和图注/结论是否对应一并核对。不能安全触发的状态记未覆盖，不根据控件存在推定完成。

完成标准：实际页数/状态逐项对应看图记录；每个可见文字区域（含位图）已读或明确标为不可辨认；每条有原文位置/截图 bbox 和来源。生成多少截图、提取多少 DOM 节点都不能单独证明覆盖完整。

## 3. 逐条判定

对清单每一条按语义与受众任务归类，再给结论。类别是分析角度，不是关键词命中器；同一句中有不同用途的分句时分开判断。

1. **否定式免责**——告诉读者“本页/本文不做什么”。回答隐私、计费、数据删除、权限等真实顾虑的必要边界可以保留；依据语义用途判断，不依据是否包含否定词。
2. **实现策略外泄**——把取数、路由、优先级、回退、同步规则当成面向读者的说明；在 Skill 或工程文档中，若它是执行所需的规则则保留，否则视为重复或泄漏。
3. **制作/验收说明当文案**——把素材取舍、排版指令、审查待办、未来补图、制作者自我约束或测试目的写给观众。给出具体删改或移至制作记录的建议；必要的事实限定单独保留。
4. **元文案自述**——“这里展示…”、“本页用于…”或解释文档/页面为何存在；职责已经由标题、结构或元数据表达时，通常删除或改写。
5. **内部代号与技术标识**——服务名、仓库名、组件名、hash、Release ID；受众不认识，或认识但无法据此采取动作。
6. **无动作信息**——只呈现状态不给下一步；异常时读者不知道能做什么；标识符不可复制。
7. **占位与调试残留**——`—`、`暂无`、示例值、TODO、临时日志或调试输出随版本发布。
8. **提示词残留（文本模式重点）**——用户请求的口吻、会话上下文、模型角色/系统提示复述、一次性任务背景、隐藏推理或仅为引导 agent 当次作答的编排。判断依据是：删掉后是否损害文档作为长期规范/参考的可执行性；不损害则删除或改写。正常的规范性祈使句、步骤和安全门槛不因“像提示词”而标记。

每条结论四选一：**保留 / 改写 / 降级 / 删除**。降级指移出主要阅读路径——网站可收进 tooltip、帮助文档、日志或内部模式；文本可移到维护者注释、附录或变更记录。

防过度标记：受众本身是运维或开发时，技术标识可能就是工作对象；否定式陈述若回答受众第一次会产生的真实顾虑则可保留；对外求助所需且可复制的标识符也可保留。判不准时按保留处理并列入待确认清单，不为凑数量升级成问题。

**元案例逐句判定**：讲解制作/审查过程本身可以是正当内容，但不是整页豁免理由。明确作为教学对象引用的指令或缺陷，应有清晰引用边界、可见实例和受众用途；主讲者的制作待办、对自己的要求仍按制作说明审查。诚实的事实限定与制作指令混在一起时拆开给建议：保留影响观众理解的事实，将制作侧安排移出主讲画面。源码注释、纯讲者备注的预期受众不同，不能照搬主讲页的结论。

每条“改写”必须写出可直接替换的完整目标文案。目标文案只描述读者关心的事实和可采取的动作，用陈述句表达职责，不用否定句表达“不做什么”。文本模式的改写要保持原文件格式、语气和语义边界，不把实现规则改写成面向终端用户的宣传语。

完成标准：每条 finding 都有类别、结论、受众依据、原文位置和完整建议；保留项与待确认项说明了理由。

## 4. 复核与定级

### 文本模式

沿原文上下文复读每条 finding，确认它确实是提示词/需求外泄，而不是执行该文档所需的规范。复核重点是语义必要性、重复的元说明、读者是否会误把内部指令当成内容；不调用截图工具，也不推断字号、首屏或视觉层级。按三档定级：

- **阻断**：会让 agent 或文档读者执行错误任务、误解权限边界，或把敏感的用户/系统提示词带入长期文件。
- **应改**：纯元说明、一次性上下文、实现细节重复或无动作信息，增加阅读负担但不改变核心执行结果。
- **可选**：轻微措辞、层级或重复优化。

### 视觉模式

判定完回到真实截图，逐条把原文用 [`scripts/annotate-shot.py`](scripts/annotate-shot.py) 圈出来，包含位图内文。截图里找不到的条目退回证据清单，区分源码分支、实际可见内容与未覆盖项。定级落到理解影响：误导核心判断或动作是阻断；显著的制作说明噪音、元说明负担是应改；轻微重复是可选。位置、占比、对比度和投影可读性影响实际负担，但大字号不自动升档，藏在 details 也不自动豁免；需要展开才判断的内容先实际展开。

核对图片、文案和比较控件共同传递的结论：是否为同对象/同信息任务，必要事实能否从画面读出，标签是否与实际显示一致。关键位图太小、证据不对应、留白挤压证据或交互失效时具体记为视觉/证据问题并交制作方，不扩权修改结构或版式。采集不到的条目不做虚构视觉定级，标为未复核。

视觉模式完成标准：每条渲染面 finding 有能定位原文的标注图与整页上下文；原文不可读时只报告可见性问题，不编造原文。其余条目写明未截图原因。文本模式完成标准：每条 finding 有可复核的原文位置和上下文理由，不产生截图要求。

## 5. 输出报告

以 [assets/report-template.html](assets/report-template.html) 为骨架渲染单文件 HTML，默认写到系统临时目录并在回复中给出绝对路径；用户指定路径时写到指定位置。报告标题、摘要和证据区明确写“文本模式”或“视觉模式（网站/幻灯片）”。

视觉模式的截图先在报告里写占位符：finding 的标注图用 `__EMBED_<finding id>__`，全景图用 `__EMBED_overview:<截图名>__`；再用 `annotate-shot.py --inject <报告路径>` 就地替换成 base64 data URI。缺少注入图片时非零退出并保留原报告。成功后打开报告看图，核对原文标注、清晰度、覆盖记录和状态；注入成功不能代替视觉验收。文本模式删除截图占位符、全景图和视觉复核段，改为列出审查文件、行号和覆盖范围，不运行注入脚本。

报告必须包含：

- 模式、受众与决策结论，作为全篇判定依据。
- 输入版本/哈希、技能源码版本、执行身份/线程（以宿主记录为据）、用户已指出/本轮独立发现的来源区别。
- 文本模式的文件清单、用途、覆盖行数与未覆盖原因；视觉模式的全页清单、截图、真实看图观察、位图文字清单和交互步骤结果，以及缺口。
- 按严重度分组的 findings，每条含稳定 id、原文、类型、受众依据、结论、完整建议文案和位置。视觉 finding 带标注图；文本 finding 写原文行号与上下文。
- 原文与建议文案的对照、待确认清单，以及改写后的整页或整篇文案全文。

状态分为 `clean`、`有待修项`、`覆盖不足`。仅全部请求范围已检查、视觉模式的每页/关键位图/适用交互已复核、没有发现和待确认项时可 clean。缺视觉覆盖时即使没有 finding 也只能覆盖不足。报告中的建议始终标为未执行；本技能只读，不显示“已修改”或伪造改后截图。旧版审查不能作为新版技能行为评估结果。

## 单轮回看与限制

`node scripts/capture-surface.js --show <采集.json>` 只读汇总 DOM 条目、绘制面和资源失败数，提示哪些采集仍需人工/Agent 看图补全。报告记录已看页/实际页、位图已读/待读/不可读和交互已核对/适用项，不能把 DOM 条目数当作可见文字总数。

BB 中用 `bb thread log <id>`、`bb thread output <id>` 回看持久化的工具调用与结果；复用宿主事实与本轮覆盖记录，不另建全局账本。当前缺口是无跨轮接受率、保留窗口 rollup 或自动裁决回写；制作方可按 finding id 在单轮记录补充采纳/拒绝理由，未回复不能视为采纳。采集/注入计数只能验证产物一致性，语义与实际看图仍需独立评估。

## 不变量

- 只读：不修改被审仓库的任何文件，只写报告与截图产物。
- 不发起外部写操作（评论、工单、消息、推送）。网站采集不要为了构造状态去触发失败登录、提交表单或改配置。
- 视觉模式截图必须是真实渲染产物；拿不到就记覆盖范围限制，不用示意图、手绘或源码推断代替。文本模式以读取到的原文为唯一证据，不补全缺失内容。
- 结论只基于实际读到的文案、文本和代码；不可辨认或未定位的内容如实标注，不补全成看似合理的文本。
