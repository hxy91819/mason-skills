# Steward Sync

定期把被观察线程的进展、卡点和需要用户做的事汇总成一份短报告。观察对象每次由用户给出（线程 ID 清单，或沿用上一轮），一轮只报告：不催办、不写仓库文件、不新建线程、不给被观察线程发消息。唯一例外：用户预先授权过的异常反馈通道（如向指定管家发事实简报），正常状态不发。

## 每轮检查

1. 逐线程取状态与最新汇报：`bb thread show <id> --json`（看 status/queuedWork）、`bb thread output <id>`（为空则 `bb thread log <id> --limit 2`）。
2. 活动判定用事件库计数，不用 updatedAt（它只在回合开始/结束刷新，长回合里不变，会误报成停住）：

```bash
sqlite3 /root/.bb/bb.db "select thread_id,count(*),datetime(max(created_at)/1000,'unixepoch','localtime') from events where thread_id in ('<id列表>') and created_at > (strftime('%s','now')-<窗口秒>)*1000 group by thread_id;"
```

停住判据：超过一轮间隔仍 0 事件且无排队消息；其余都算在干活，不催。
3. 需要细节时读关键子线程的最新输出；路线对不上时读各线工作簿（`docs/steward/`，以远端分支为准）。

## 二次核实（判定前必做）

凡要写「假阻塞/停住/等用户/需要用户干预」，先自己核实、不询问线程：用事件库与 `bb thread log` 翻父线程和相关子线程本窗口会话，搜事项关键词（事项名、操作类型、MR 号、路径）。父线程最新输出只讲最后一件事，早期执行要翻回合。确认真没人执行过才写结论；核实不了的写「待核实」，不断言。

## 业务探针（可选分支）

用户要求观察业务实况（现网水位、成功率、日报到点等）时：

- 用只读命令做探针。命令取该线管家或证据目录里已验收的版本，不自造采集器；口径提醒跟着探针走：计数含义（实例行/任务行/去重用户分开）、缺失维度不补 0、不做超出样本的结论。
- 正式口径以日报或既有投递为准，探针只做即时对账。
- 异常按用户授权通道发事实简报，正常不发消息。

## 报告格式

时间以事件库 localtime 为准；跨机时钟先互对再下结论，不拿单个 shell 读数判定偏慢。

1. 首行 **⏱️ 同步 HH:MM（窗口 HH:MM–HH:MM，北京时间）**；下一小段用固定句式交代各线（「N 条线：A 是…，B 是…」），给新读者上下文。
2. 每线一节 `**A｜<名称>：<status+emoji>**`，下接 emoji 列表 `- <emoji> **事项名**：<一句话>。` 只写本窗口变化；没动写 `- 🔄 **事项名**：无变化。`
   emoji 口径：✅ 收口，🟢 健康推进，🚧 进行中/在写，⏳ 等用户或外部，🟡 部分完成，🔴 卡住或报错，🔄 无变化。
3. 多行细节用表格 `| 事项 | 状态 | 说明 |`，**逐行列数写满**，状态 emoji 只放状态列，不塞进事项列。
4. 用户要操作的 MR 用超链接短形态 `[!iid](完整地址)` 放事项列，说明列不放裸链接；每 MR 配一句改动说明。
5. 末尾 **需要你干预** 表格：列用户真正的手工动作，不是「所有待办」——需要本人审批合入的 MR（能自动合并或由其他 reviewer 处理的不列，如开源镜像方向的 MR）、需要用户排查或协调的事项（找人、对外沟通、只有用户知道的输入）、需要用户拍板的决策。**按项目分组：每个项目一小节，节标题写「<项目>（<对接线名称>）」；跨项目或项目无关的通用事项放「跨线/通用」小节**。每项一句说明；无则写「本轮无待干预事项」。
6. 与上一轮清单合并去重：已解决的下掉，其余保留。
7. 被观察线程对 advisory 输入的否决/拒绝/改形，点名「被拒绝」并附依据，不淡化。

## 表达规则

先给读者上下文，再写 ASD-STE100 风格简体中文：短句、一句一个意思、主动语态、常用词不造词、名词用各项目工作簿和 GLOSSARY 的固定说法。正文不写线程 ID、提交哈希、版本号、内部包名这类技术标识；只有用户要操作的对象可写（MR 编号、日期、阶段号）。

## 定时接入

用户要求按间隔滚动时，用 BB 会话型定时任务（CronCreate）：分钟位避开整点/半点；保持会话内有效、不落盘，并提示「会话结束即失效、7 天自动过期」。恢复时先找上次的 prompt 备份再重建，别凭记忆重写。观察对象接任/退役的当轮，直接改指向并在报告里说明。
