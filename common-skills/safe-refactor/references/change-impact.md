# 影响面分析（change-impact）：验收谁，取决于实际影响谁

## 输入和读取

输入：目标、`mode=plan|actual`、固定旧版／候选版、现有 policy 和工作单。信息不全时先从仓库取得，不编造路径或 SHA。

读取 [共享规则](workflow.md) 和 [影响报告模板](../assets/impact.md)。需要风险维度时读 [检查清单](checklists.md)。

只写本任务的影响报告和策略草案；不修改生产代码、基线答案或已批准策略。

## 1. 从变化的语义出发

`plan`：审查准备改变的边界。`actual`：检查真实完整 diff，包括新增／删除／重命名、依赖锁文件、生成物、配置、迁移、测试和 CI。

逐项说明“以前怎样，现在／计划怎样”，不能只列修改文件。尤其检查：

- 输入输出、默认值、错误、权限、排序、分页、重复和缺失项。
- 事务边界、锁、写入可见性、快照、幂等、重试、取消、关闭、重启。
- 共享状态、表结构、缓存键及失效、事件内容与顺序、队列与连接池。
- 同步变异步、新的 await、并行批量化后，哪些前提需要重新检查。

先确认文件和符号存在再读取。搜索失败、解析不完整、Git 对象缺失是工具限制，不是不存在。

## 2. 追踪两张关系网

**调用网**：从修改组件反向到 API、事件处理、后台任务、定时任务、CLI、插件和外部消费者；再检查这些入口的依赖假设。

**影响网**：谁读取它写入的数据？谁订阅它的事件？谁共享缓存、锁、连接池、队列、CPU 或部署配置？没有直接调用仍可能受影响。

每条链路附实际 `文件:符号/行号@revision` 或运行证据。分为：

- `affected`：有证据确认受影响。
- `possible`：存在合理传播路径但未证实，列所缺证据。
- `unaffected`：有具体边界证据支持，不是“没有搜到”。

动态注册、反射、跨仓库、外部插件／客户端、生成代码和平台配置看不全时保留 unknown；说明哪项未知会阻止当前方案。

## 3. 对齐行为契约和证据

每条影响链路关联契约 ID。每个契约写清：需要保持的行为、依据、被什么具体测试和断言保护、缺口是什么。

组件契约测试不自动覆盖调用方假设；调用方端到端成功也不自动覆盖组件的错误与时序语义。按实际风险选择两者组合，不要求所有系统分支穷举。

已有证据区分 `exists / executed / current / meaningful`：文件存在、跑过、对应当前版本、确实断言目标行为是四件不同的事。

## 4. 选择改造路径

比较以下成本，不机械偏向任何方案：实现、建立可信 oracle、跨调用方验证、未来维护、资源影响、恢复。

- **local**：保留其他调用方原路径；优先隔离变化的执行策略，必要时有限复制。列重复规则的维护责任和退出／长期保留条件。不得增加第二套权限、权威状态或隐式双写。
- **shared**：确实要改变共享语义；明确消费方式分类和必须验证的消费者，不因为调用方太多就只跑组件单测。
- 两者均不能支撑收益：推荐减少目标、拆成渐进步骤或暂不改。

必须给明确推荐、依据、最小验证集合和一个关键取舍，不能只输出“建议增加测试”。

## 5. 输出可执行边界

更新 `impact-plan.md` 或 `impact-actual.md`。策略草案包含：允许路径、保护路径、基线准备路径、需冻结的断言路径、契约和收益要求。

路径是机械辅助：相同文件里的新缓存副作用仍可能越过语义边界。路径模式只用仓库相对 POSIX 路径；详见 [工具说明](tooling.md)。

`actual` 必须额外列：原计划没有的新链路、新的语义变化、受损的断言、哪些旧证据已过期。与真实候选 SHA 绑定。

## 停止和返回

- 新影响超出批准范围：输出 `REPLAN`，不自行改大白名单。
- 无法证明关键边界：输出 `INSUFFICIENT`，说明补哪项证据或怎样隔离。
- 可以在现有边界验证：输出 `READY_FOR_BASELINE` 或 `READY_FOR_VERIFY`，不是业务 PASS。

## 输出格式

```text
策略与结论：<local/shared/reduce/stop>，一句话原因
变化 → 消费者／共享资源 → 契约 → 具体证据 → 缺口
新增影响：<与上轮不同的项目>
建议动作：<谁做什么、最小验证集合>
未知项：<影响决策的具体限制>
```

例如：“加载器 X 从逐条失败改成整批失败；定时任务 Y 依赖部分成功，但现有测试只看总数。建议给接口 A 新增批量策略，不修改 X 默认语义；另测排序、重复 ID、租户过滤和连接池影响。”
