# 原型对齐审查

原型是规格的三层之一：视觉由像素与结构门禁守，领域规则由领域审查守，这个技能守中间那层——**功能设计**。功能存在不等于功能设计一致：验收结果被预选、默认值从 3 变成空、下拉选变成填 ID、只知店名就找不到案场，都是功能存在而设计走样。

只产清单，不改代码；修补由派发方另行安排。

## 第 0 步：环境探针

读任何代码之前，先用派发方给的入口与账号各做一次实际登录并截一张图：原型一张、正式一张，图上必须是登录后的页面（看得到用户名或导航），登录表单截图不算探针通过。两边都通过才继续；任何一边打不开，立刻停下，把失败的入口、账号与错误原文报回派发方，不要转成「只读代码的推导报告」——没有实测的对齐审查不是这个技能的产出。派发方明确要求「程序推导模式」时才例外，且报告每一条都标「程序推导」。

基准代码用只读 worktree（`git worktree add /tmp/<name> <base>`），审完移除；不在主工作区读。

探针常见的三种卡法与处理：登录被限流（429）就等限流窗口过了再试一次，仍不行报回；原型端口被占就换一个端口偏移，占用端口的进程不是你起的就不动它；账号或密码派发方没给或给错，直接报回要，不猜。登录 POST 是探针的一部分，不算业务写入；拦截业务写入从登录后开始。

## 先读

1. 项目的移转约定（原型哪些是示范手段不搬、哪些差异已裁决、授权在哪判）。找不到就向派发方要，不自行判断什么算示范手段。
2. 项目术语表与本次范围内页面对应的领域文档节。
3. 范围内每个页面的原型文件与正式文件。派发方给的路径找不到时，按页面标题或功能文案 `rg` 两边源码定位（组件常被改名或搬目录），定位结果写进报告的「范围」节。

## 比对维度

对范围内每个页面 × 角色 × 阶段，逐维度过，每个维度都写结论（一致也写）：

| 维度 | 看什么 |
| --- | --- |
| 输入方式 | 文本框／下拉／可搜索下拉／stepper／日期／单选多选；原型是选，正式变成填，就是差异 |
| 候选来源 | 选项从哪来、是否全量、是否截断（前 N 笔）、是否可搜索、搜索比对哪些字段 |
| 默认值 | 预选／预填／带入本人资料／空；原型空而正式预选，是差异 |
| 必填与校验 | 必填项、格式、何时提示、是否代填（原型要本人填「无」，正式自动补「无」，是差异） |
| 条件显示 | 哪些区块随选择展开、随数量出现、随角色与阶段出现 |
| 动作后导向 | 提交／取消／返回去哪、停在哪个页签、是否清空 |
| 列表 | 筛选项集合、时间条件的语义（含不含迄日、筛哪个事件）、文本搜索覆盖字段、排序、分页、清除条件、各页签计数 |
| 空状态 | 资料空与搜索空是否区分、是否给出清除或建立入口 |
| 可见范围 | 同一角色在原型能看到、正式看不到的区块；先对照移转约定里的授权投影规则，再判是否差异 |
| 错误定位 | 缺项是否定位到字段、是否聚焦第一个缺项 |

每个维度的判断依据是原型文件的行与实际操作，不是对原型的印象。先前的对比报告、修补 PR 说明、聊天记录都在审查做完之前不读：它们描述的是过去某个 commit，读了会把旧结论写进新报告。派发方要求对照旧报告时，放在报告最后一节，审完再读。

## 分级

按使用情境定级，与改动大小无关：

- **P1**：用户在该情境下做不下去或容易写入错误结果（不知完整电号就建不了单；验收预选让人一键通过）。
- **P2**：要额外操作或少一项能力（要另选单号再复制；筛选少一个字段）。
- **P3**：提示、顺序、回复细节。

## 证据

- 每条差异引原型文件行号与正式文件行号，附并排截图（原型在左，正式在右，同角色同阶段）。行里写的「原型行为」「正式行为」必须能在该行引用的截图上看到；写行之前重新打开截图确认元素在场，看不到就不写这一行。行号引的是当次基准 commit 的文件，引用前 `sed -n` 把那几行读出来核对。截图用 Playwright 以同一视口各截一张，再拼成一张；命名 `<页面>-<角色>-<阶段或状态>.png`，单边图加后缀 `-proto`／`-formal`。
- 只做只读操作：查询、选取、展开、切页签、未保存的表单。业务提交在浏览器层拦截；截图只证明画面与非提交互动。
- 程序推导（没有实测）的条目单独标明。
- 没有证据的差异不列。

## 自行引入的判断

审查者决定不列为差异的项，单独成节，每项附依据：哪条移转约定、哪条 ADR、哪条决策。派发方靠这一节核对两种错误：把已裁决的「不同」误报成差异，或把未裁决的「缩水」当成接受。

## 报告格式

写到派发方指定的路径。结构固定：

```
# <范围> 原型对齐审查

## 范围、基准与证据读法
原型版本、正式 commit、实测日期与视口、使用的角色账号、截图目录、只读操作的边界。

## 统计
总项 N，一致 M，差异 K（P1 a／P2 b／P3 c）。

## <页面分区一>
| 编号 | 页面／功能 | 原型行为 | 正式行为 | 分级 | 证据 | 建议修法 | 需契约或后端改动 |
一致的项也列，分级写「一致」。

## <页面分区二> …

## 自行引入的判断
| 编号 | 不列为差异的理由 | 依据 |

## 验证与未完成项
没打开的页面、没登录的角色、没实测只推导的条目。
```

编号用前缀加流水号（如 F01），跨报告保持稳定以便派发引用。

## 完成判据

范围内每个页面的每个维度都有结论；每条差异都有两边行号与截图，且截图上确实有行里描述的元素；统计数字与表格行数对得上；自行引入的判断每项有依据。缺任何一项，报告不交——改为报回缺什么、卡在哪一步，让派发方补资料或换环境。一份「统计全为 0」的报告没有价值。
