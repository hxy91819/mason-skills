# 生产账号与共用账号上的操作方式

这是一个由 Agent 操作生产账号的项目实际用过、证明可行的做法：人只发放临时管理员密钥、负责拍板，Agent 负责执行和留证据。

## 临时管理员密钥

- **只放在执行进程的环境变量里。** 不写进文件、命令行参数、日志、IaC state 或 tccli 配置，也不打印。
- **执行前先确认账号。** 用 `GetCallerIdentity` 核对当前密钥属于目标账号。
- **回执发布前做一遍凭据扫描。** 那个项目覆盖了约 80 种凭据形态。
- **一批操作做完就让发放人销毁密钥，并回读确认已经失效。** 注意：删除密钥不会让已经签出的 STS 临时凭据立即失效。

## 按精确 ID 审批

- 每批管理员操作写成一份 JSON，列出精确的动作、资源 ARN 和参数，并附上 SHA256。这份 JSON 经 MR 合入、真实 CI 通过后才执行。
- preview 一旦出现批准范围以外的差异，就停下。
- 能 DryRun 的先 DryRun，例如 `UpdateAddon`。
- 每次写操作前记下意图，写完记下 RequestId。
- 结果不明的不要重发，先回读确认。
- 明确被拒绝的只归档；换了参数就要重新批准。
- 修复批次的前置条件写"现在应当是什么样"，已知故障也写进去，例如"某应用 Unknown，报错只指向待补的权限"。写成"一切健康"，修复会被它要修的故障挡住，只能再走一轮审批。
- 用一次性 nonce 加锁，防止同一批被重复执行。

## 多个业务共用的账号

- **只动自己登记过的资源。** 按精确 ID 操作，不要按名字前缀列出来再批量删除。共用的测试账号里可能有几百个别人的域名和资源。
- **只采集汇总数据**，DNS 之类的身份只授权到单个域。

## 告警渠道验证

- **演练只发到一个静默的验证接收端**，不发到真人所在的群。曾有一次往群里发了通道测试，再加上一批真实告警，用户一天收到 19 条消息。
- **触发要真实。** 用隔离的短期证书之类触发真实规则，再按 fingerprint 加 startsAt 把触发和恢复配成一对，作为证据。
- **企业微信机器人返回 `errcode=0` 不等于有人看到。** 它限速每 60 秒 18 条，遇到 45009 就暂停。
- **预算通知的 `ReceiverIds=[]` 表示走默认订阅。** 审计邮件、预算通知这类，最终是否送达只有接收人本人能确认，把它列成接收人的待办。
