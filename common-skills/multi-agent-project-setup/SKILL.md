# 多 Agent 协作项目的初始化配置

单人项目的默认配置在十几个线程并行时变成一条单车道：每个 MR 跑全量 CI、master 一动就重跑、状态记在共享文件里、等待挂在会话里。一个四人团队带十几个 Agent 并行开发的平台项目 2026-11-05 实测：每天 130 个合入，工作 MR 从建到合入 p50 41 分钟、p90 106 分钟，一半 CI 容量花在记账 MR 上；数字与事故见[实测证据](references/field-evidence.md)，向用户出示依据或判断自己项目是否同病时再读。

每条配置过一遍**二十线程测试**：二十个线程同时这么做会怎样，会不会互相拖住。

## 原则

- **门禁只保护别人**：合入前的检查只为保证别的线程 rebase 到的主干能编译、单元测试绿；其余检查合入后跑，红了告警、向前修。没有生产用户时成立，开放用户后按环境重新评估。
- **共享状态出仓库**：会被多线程同时改的东西（工作簿、台账、证据）放本机被 git 忽略的目录，或拆成每阶段一个文件。
- **等待不占会话**：超过 20 分钟的等待放持久进程，结束时唤醒线程。
- **规则进检查**：能用 lint 或 CI 保证的约定做成检查，不写成提醒。
- **环境只从主干来**：共享环境的每类变更只有一条登记过的通道，排障只读。
- **有数才有判断**：队列、滞后、停摆、机器健康都有指标、阈值和告警去向。

## 流程

1. **量基线**，至少半天样本：合入数与构成（工作 / 发布 / 记账）、工作 MR 从建到合入 p50 与 p90、CI 墙钟与取消数、检查池并发与排队、发布滞后、同时活跃线程数、开发机 load。样本不足半天不下结论。
2. **逐项对照清单**，缺项按"做法"落地。整改顺序固定：先减少走全量 CI 的 MR 数，再减少每个 MR 的 CI 轮数，再把容器类检查挪到合入后，最后才加机器。
3. **同口径复测**，写进项目的 operations 记录。门禁改动先落地，再用自然流量验收，不为凑样本等。

完成判据：清单每行都有"已有 / 已落地 / 不适用（原因）"三选一，复测数字与基线并列。

## 配置清单

### 仓库与文档

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| 主检出留主干，每个任务独立 worktree，交付后 `git worktree remove` | 十几个线程改同一检出会互相覆盖 | `git worktree list` 没有超过一天的闲置 worktree |
| `.local/` 进 `.gitignore`，作本机状态目录（工作簿、证据、临时产物） | 这些内容进仓库就要走 MR 和 CI | `git check-ignore .local/x` 通过 |
| `AGENTS.md` 只放常驻规则加"任务 → 先读"路由表，细节按任务加载；读文档先 rg 标题再按章节读 | 一次 cat 多份文档会截断，Agent 还要补读 | `AGENTS.md` 一屏内，路由表每行一个任务 |
| 术语表加 ADR，名词只有一个写法 | 名字撞车让线程各改各的 | 新名词先进术语表再出现在代码 |
| 数据库迁移编号用 UTC 时间戳 | 顺序号在并行分支上抢号 | 迁移文件名匹配 `YYYYMMDDHHMMSS_` |
| 会被多方追加的登记表和账本：一条记录一个文件，读取时组合；CI 禁止往汇总文件追加，加载器遇到重复键报错 | 并行 MR 都往文件末尾追加，反复冲突；有一次 git 合并没报冲突，YAML 里却多出同名顶层键，旧状态被静默覆盖 | 汇总文件只剩索引字段；两个分支互相 rebase，两个方向都无冲突 |
| 建 worktree 的工具从最新主干建分支，并打印落后的提交数和近 7 天规则文档的变化 | 一个线程落后主干 17 个提交，照旧规则跑了 18 分钟全量检查 | 新建 worktree 的输出里有落后数和规则变化 |

### 合入与 CI

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| 合并结果 CI 一次绿灯即合入；master 漂移只评论留证，不重跑（双边都新增迁移时例外） | 漂移重跑让每个 MR 跑两三轮，合入要一小时 | 合入工具日志里没有"重跑" |
| 主干检查每次合入触发，正在跑的跑完，排队的只跑最新提交（superseded 跳过，不用 cancel-in-progress） | 取消策略下合入密集时主干检查一次都跑不完 | 任一小时内主干检查至少一次成功 |
| 门禁三层：合入前只跑弹性公共池上的静态检查；改迁移、镜像、部署输入时才在合入前跑容器类；合入后主干检查跑全部 | 容器类检查占自有检查池，是排队的根源 | 纯 Go 或前端改动的 MR 墙钟 5–6 分钟 |
| 纯文档 MR 只跑链接检查，不占自有检查池；用于编译或测试输入的 `.md` 按例外清单走全量 | 文档 MR 走全量白占 14 分钟 | 文档 MR 墙钟 2 分钟内 |
| 统一合入工具：核对远端头、MR 快照、检查对应的 SHA 三者一致，快照陈旧用工具刷新 | 线程用 close/reopen 刷新快照，顶掉正在跑的构建 | 取消数里没有同 SHA 替换 |
| 一个阶段一个 MR，审查修复进同一 MR | 一个任务开十几个 MR，每个都占一轮 CI | 分支名对应的 MR 数为 1 |
| 自有检查池并发按机器 load 和内存定，排队中位超过 5 分钟再加节点 | 机器没满时加机器不解决问题 | 检查池 load、可用内存、排队中位三个数并列 |
| 主干红时，先按失败用例名或固定标题标记搜在途的修复 MR，有就等它合入再 rebase；自己修时标题带同一个标记 | 主干红时所有 MR 一起红，各自在自己的 MR 里修，会修出好几份 | 修主干的 MR 标题都带这个标记 |
| 按路径分流时，用 `git diff --name-only -z` 读取路径，只算 `merge-base..HEAD`；白名单之外的改动一律走全量 | 按行读取时中文文件名被转义，纯文档 MR 被判成代码改动；拿目标分支 HEAD 比较，把目标分支新增的代码也算了进来，白跑约 10 分钟检查 | 含中文文件名的纯文档 MR 走文档通道 |
| MR 检查用 `BASE_SHA` 证明历史迁移没被改过，缺 `BASE_SHA` 就失败 | 历史迁移被改，库里已经执行过的版本和代码对不上 | 改历史迁移的 MR 必红 |
| CI 平台声明的语义要实测：含 bash 语法的步骤显式用 `bash -euo pipefail` 调用；排队超时和执行超时分开设 | 公共池声明了 bash，实际仍用 `/bin/sh` 启动；构建机并发配小时，排队超过默认 10 分钟就报失败 | ShellCheck 按实际解释器跑 |
| 测试前清掉 CI 事件变量，设 `LANG/LC_ALL=C.UTF-8` 和 `TZ=UTC`；测试用系统分配的端口 | 测试里新建的 git 仓库继承了 CI 变量，去远端 fetch，11 次主干检查红了 7 次；C locale 下中文报错不可读；固定端口互相冲突 | 满载重放 200 轮零失败 |
| CI 机器上的临时容器和匿名卷经统一入口创建，打上"受管"和到期时间标签，每次作业开始先回收到期的；`docker rm` 必须带 `-v` | 任务被取消或被 SIGKILL 时 trap 不执行；`rm -f` 不带 `-v`，9 天积了 1259 个匿名卷、274G | 强杀后由下一次作业回收；检查脚本拦下不带 `-v` 的 rm |

### 发布

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| 合入即自动发布到共享测试环境，安静窗口批量，发布不等主干检查 | 验收等发布的时间直接进每个线程的周期 | 合入到环境版本命中 p50 在安静窗口设计值内 |
| 非核心组件（运维、金丝雀、观测附加件）独立 Application 或后发，失败不挡核心；测试与生产同一渲染器 | 一个非核心服务 CrashLoop 挡住所有人的修复上环境 | 非核心 Degraded 时核心仍能滚动 |
| 统一发布等待工具，分开报告配置收敛、公共入口首次命中、全部副本稳定 | 各线程自写 watcher 结论不一致，黑盒测试跑在新旧混版上 | 黑盒与 e2e 在副本稳定之后才开跑 |
| 发布后的检查被下一次发布打断时，用 `git merge-base --is-ancestor` 证明它已被一个零失败的后代版本接替，记 superseded，不记失败 | 合入密集时，发布后的检查经常被打断，误报满屏 | 每个 superseded 都能指出接替它的版本 |
| 成功证据绑定内容：迁移 Job 名由配置、镜像、Secret 派生；非核心组件的放行标记绑定本次出版提交；MR 重开后只认新注册的构建 | Job 名不变时会误用上一次的成功状态；旧构建晚完成，会冒充新一轮的结果 | 改动任一输入都会生成新的 Job 名 |
| Secret 先登记为已投递，再合入引用它的配置；新组件默认 0 副本，Secret 到位后用另一个 MR 启用 | 引用先于 Secret 合入，缺 Secret 的 Pod 拖住整个应用的同步 | 引用未投递 Secret 的配置在合入前就失败 |
| 共享环境的变更只走四条通道：云资源经 IaC，集群应用经 GitOps 发布 MR，集群引导和运维操作经登记脚本并留操作记录；禁止控制台和手工 kubectl，排障用只读身份 | 二十个线程共用一个测试环境，手工改动既复现不了，也查不到是谁改的 | 只读身份之外，没有人对集群和云资源有日常写权限 |

### 协作状态

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| 管家工作簿与要求帐放 `.local/steward/`，本地 git 提交；没有目录用 `$bb-steward` 的 `init` 建 | 工作簿进仓库每次更新一个 MR，一天 30 个记账 MR | `git status` 里见不到工作簿 |
| 证据、复盘放 `.local/evidence/`；复盘按返工、P1、卡住、超时等信号写，不固定每任务都写 | 复盘里的坑汇总后变成检查或工具 | 复盘建议落到检查、工具或文档，不落到常驻提醒 |
| 并行任务书里每条验收对到有权改相关文件的线程；共用的锁定版本提前排序 | 验收落在禁改文件里，线程做到一半求助 | 任务书"不碰"一节与验收逐条对过 |

### 派发与会话

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| 派发并发按 provider 配置上限（`$bb-model-routing` 的 `max_concurrency`），满额等线程结束再派 | 一天建 168 个线程，远超通道吞吐，靠人判断队列落不了地 | `bb-dispatch --concurrency-status` 的 used 不超过 limit |
| 分档以 `$bb-model-routing`「判断与调用」为准，本文不复述 | 档位条件只维护一处 | `bb-dispatch --history-summary` 看各档接受率 |
| 超过 20 分钟的等待用线程级持久终端，结束后 `bb thread tell` 自己 | 空闲 30 分钟会话被回收，后台进程被杀，CI 绿了没人合 | 等待进程不在 provider 会话里 |
| 会话过大（几十 MB）或 turn/start 超时的线程改派新线程，按入库文档接手 | 重试无效，旧线程接收不了新任务 | 长任务的进度写在仓库或 `.local` 文档里 |

### 本机

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| `check-fast` 内循环只跑受影响部分；完整检查推送前跑一次 | 本地全量 3–9 分钟，一个任务跑四次 | 典型改动 check-fast 2 分钟内 |
| 完整检查全局限并发（如 4 个），超出排队并打印在等谁；按 worktree 的锁保留 | 32 核机器 14 个线程同时 check，load 26 | 两个 worktree 并发检查都能完整跑完 |
| lint 进程锁、临时目录、工具 venv 按 worktree 隔离；构建缓存共享；依赖安装按锁文件哈希跳过 | 跨 worktree 锁互斥、共享 venv 绝对路径失效、每次 `npm ci` | 复用缓存前能启动真实工具入口 |
| Go 统一设 `GOFLAGS=-trimpath`，再让各 worktree 共享 GOCACHE | 缓存键含源码路径，每换一个 worktree 就整套重编，缓存一小时涨约 17 GiB | 第二个 worktree 构建时 0 次重编 |

### 观测

| 做法 | 为什么 | 验证 |
| --- | --- | --- |
| 一个观测脚本定时采：MR 排队、取消、失败、墙钟中位；主干检查最近一次状态；发布滞后；检查成功却无人合入的 MR；检查池 load、内存、盘、泄漏容器；子线程几小时无新输出（比最后一条日志的哈希，不看 `updatedAt`） | 用户指出的问题，先问能不能自动检测；du 在大盘上超时返回空值，盘满了也没人知道；线程干活时 `updatedAt` 不变 | 每项有阈值；读不到值也算告警 |
| 只在异常时唤醒管家，同一问题几小时内只唤醒一次；正常发布不通知 | 没问题的提醒是噪音 | 唤醒消息里没有重复项 |
| 告警演练只发到验证接收端，不往真人所在的群里发测试消息 | 通道测试加上一批真实告警，用户一天在群里收到 19 条 | 群里只出现真实告警 |
| 要把某项检查前移到合入前，先采样失败归因，并先把检查变快 | 26 次 MR 失败里真失败 16 次，其中 10 次本机能抓；但对应检查本机要跑 809 秒，直接前移会拖慢所有线程；按文件并行后降到 255 秒 | 前移的决定附上采样分母和检查耗时 |

## 反模式

都在同一个实测项目踩过，判断依据见证据文件：

- 漂移重跑最多两轮，合入一小时。
- 主干检查 cancel-in-progress，80 分钟没有一次成功，看着绿其实没测。
- 工作簿进仓库，每次更新一个 MR 走全量 CI。
- close/reopen 刷新 CI，63 次取消里 47 次是它。
- 后台等待挂在会话里，空闲回收后 CI 绿了没人合。
- 按管家上下文用量强制交接；交接按信号（会话出错、模型降级、turn/start 超时）。
- 只拆测试环境不拆生产：拆就在同一渲染器里两边一起拆。
- 把源码复制到 `/var/tmp` 跑检查，Go 缓存从每任务一份涨到 42G。
- 把"重要"当"难"：按返工风险和是否长期留在生产里定档，不按重要性。
