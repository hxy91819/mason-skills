# Review HTML Report

把已有审查结果渲染成一份只讲「问题 + 对比」的报告。审查结论和执行权限由上游负责，本技能只消费已有记录、生成报告并验证展示。按名称由宿主加载本技能；脚本从本技能解析后的根目录运行，不依赖调用方的安装位置。

## 输入与生成

读取 [references/report-data.md](references/report-data.md)，把已有 findings、状态和证据映射为 JSON。两个上游默认交付 HTML；用户明确只要文字时由上游跳过渲染。

```bash
python3 <本技能根目录>/scripts/build-report.py --data <记录.json> --check
python3 <本技能根目录>/scripts/build-report.py --data <记录.json> --out <报告.html>
```

路径参数使用绝对路径；含空格时加引号。报告写到用户指定产物目录或临时目录，返回可点击链接。默认不发布到外部站点。

## 展示契约

每个问题只出现一次。问题卡默认折叠，标题行有严重度、id、页和处理状态，便于多问题时快速定位；展开后依次是一句核心变化、一处对比，以及折叠的「理由与处理」。卡片按视觉/内容分组，组内按严重度排列；「全部展开」只展开问题卡。

对比按问题类型三选一，图片在报告里只内嵌一次：

- **已修视觉项**：真实前后滑块，可切换并排（复用同两张图）。两张图须同画面、同视口、同滚动位置，以改动元素滚入视窗为锚，分别用 `beforeBox/afterBox` 红框标改动点，附 `lookHere`。两图相同时不出滑块。行为修补用 `steps` 逐步给出双图。采集与坐标细节见数据契约。
- **未修视觉项**：一张红框问题图（`annotatedImg` 或 `img`+`box`）；不提供则只有文字。
- **文字项**：原文与改后/建议左右对照，逐字标出删除与新增；未执行项标「建议 · 尚未执行」。

页头只有状态和问题数；影响结论的缺口在「覆盖范围限制」中展示。`metrics` 和 `context` 折叠在末尾。逐页覆盖、过程记录和全量截图留在本地 JSON，不进报告。

## 验证与完成

`--check` 校验字段、图片并输出覆盖/分组状态；已修视觉项的每组前后图缺任一有效红框或尺寸不同都会进入 `limits`，报告不能标完成。它只检查记录一致性，不证明审查者真的看过图。

生成后在浏览器检查折叠、文字换行和证据可读性；有滑块时检查极值、中点、并排往返及 resize。已有报告需要更新时先完成数据/图片校验，失败保留原 HTML。交付 HTML 链接、输入记录位置和剩余展示缺口；不据渲染成功改写上游审查结论。
