# 新用户体验测试：让便宜模型扮演第一次接触产品的 Agent

适用于用户是 Agent，或是"用户加上他的 Agent"的产品，接入方式包括 Skill、MCP、CLI 和 SDK。每个 MR 的测试只证明单个部件符合规格。没有任何测试证明：一个只看过公开文档的新用户 Agent，能把一件真实的事做完。这份做法在项目 W（见[面向 Agent 的云端执行平台复盘](../agent-platform-lessons.md)）跑了三轮，每一轮都找到 MR 测试漏掉的问题。

## 为什么值得做

三轮里找到的、MR 测试没有覆盖的问题举例：

- **接入面板只统计 SDK 通道**：用户经 MCP 调用后，面板仍显示"未开始"。修这个问题的 MR 测试全绿，因为测试只覆盖了 SDK 这一个通道。
- **宿主默认把 MCP 工具藏起来**：某宿主默认不把 MCP 工具声明给模型，要模型自己去搜。照接入页配好以后，模型以为自己没有工具可用。
- **大文件走了 base64**：模型把本地文件 base64 编码后塞进 JSON 工具参数上传。大文件又慢又容易超限，而文档没写大文件该走 HTTP 文件通道。
- **系统级 pip 被拒**：云端镜像遵循 PEP 668，系统级 `pip install` 被拒绝，Skill 里没写要先建 venv。
- **模型自己写轮询**：没有等待工具时，模型用 shell 循环加 sleep 轮询操作状态。加了"单次最多等 60 秒"的等待工具后，它不再自己写轮询。
- **停机没有预期时长**：停机比用户预期的慢，界面上也没写大概要多久。

从注册到本地拿到成果，首轮用了约 14 分钟，第三轮约 8.5 分钟。第三轮里 Agent 真正干活不到 3 分钟，其余时间都花在接入准备上：下载 Skill、建凭据、OAuth 授权。

## 角色与隔离

| 角色 | 由谁扮演 | 能看什么 |
| --- | --- | --- |
| 用户本人 | 外层测试 Agent | 只看公开入口：首页、控制台，以及控制台给出的 Skill 下载和 MCP 接入说明。不读源码仓库、内部文档或别人的测试记录 |
| 用户的 Agent | 外层启动的嵌套 Agent 会话 | 只加载按控制台指引下载的 Skill 和配好的 MCP；不加载全局技能、全局 AGENTS.md/CLAUDE.md 和全局 MCP 配置 |
| 平台 | 被测的测试环境 | 只动本轮新建账号下的资源 |

- **账号**：用公开注册表单新注册一个专用账号，名字带上轮次前缀。账号和 Key 存在工作区的 `.private/` 里，不写进报告。
- **工作目录**：用空目录，不放项目文件。示例数据由外层现场生成，例如约 2000 行的销售 CSV。
- **嵌套 Agent 的配置**：配置目录独立，例如 pi 设 `PI_CODING_AGENT_DIR=<工作区>/.private/agent`，只复制模型鉴权需要的文件。启动参数关掉技能自动发现和上下文文件，只显式加载下载的 Skill：

  ```bash
  PI_CODING_AGENT_DIR=<工作区>/.private/agent \
    pi --model <便宜模型> --no-skills --skill ./skills/<name> --no-context-files -p "<任务原文>"
  ```

- **OAuth 同意页**：由"用户"去点。外层用 headless Chrome（路径读 `$CHROME_BIN`）带着登录会话打开授权链接，点同意。
- **长命令**：用编排环境提供的长任务包装器运行，避免空闲会话被回收时连带杀掉后台进程。

## 任务怎么写

- **任务原文**：就是用户会说的一句话，写明目标和交付位置，不提示该用哪个工具。例如："我本地有一份销售数据 data/sales.csv。请在云端工作空间里用 Python 分析每月销售额和各品类占比，生成一份带图表的 HTML 报告，把报告和图片取回到本地 output/ 目录。做完把工作空间停掉。"
- **覆盖主链路**：这一句话走完了创建、上传、装依赖、执行、取回、停止整条主链路，换别的任务也要做到这一点。
- **追加的话**：外层可以像用户一样追加一两句话推动进度，但每句都要记下来。需要追加，本身就是一条体验问题。
- **用便宜模型**：成本低；弱模型也更早暴露文档歧义，强模型往往自己猜对，问题就藏住了。模型要显式指定，不依赖派发路由的默认选择。

## 观察什么

- **嵌套 Agent**：读完 Skill 后怎么决策，调用了哪些工具、按什么顺序，在哪里卡住或重试，报错能不能帮它自己恢复，最终产物对不对。
- **用户本人看到的页面**：外层顺手看控制台，包括接入面板状态、凭据列表、用量页和操作记录。这些单独写成"观察记录"，不告诉嵌套 Agent。

## 报告格式

- **总体**：从注册到本地拿到成果的总时长，拆成"接入准备"和"Agent 干活"两段；最顺和最别扭的地方各列 3–5 条。
- **时间线**：用 UTC 时间。
- **问题清单**：分 bug、体验问题、设计局限三类。每条写现象、复现步骤、UTC 时间，有 request_id 就写上。只写亲眼看到的。
- **建议**：按优先级排。
- **附件**：截图，以及嵌套会话的关键过程摘录。摘录里去掉密码、Cookie、token、API Key、授权码和 base64 数据。

## 收尾

- **云端资源**：停止或删除本轮创建的工作空间；撤销本次 OAuth 授权；撤销本次创建的 API Key。有一轮漏了撤销 Key，留下一枚孤儿 Key，只能等它过期。
- **本地文件**：删除 `.private/`，里面有账号、Key、嵌套 Agent 目录和浏览器配置。
- **线程绑定**：工作区或证据目录如果绑定在编排环境的测试线程上，先归档线程，再删目录。

## 分诊与节奏

- **逐条定性**：编排者给每条问题定性。bug 进修复阶段；体验问题改文案、文档或交互；设计局限交给用户做产品决策，附上推荐，用户可以暂缓。再按区域分给产品或环境负责人。
- **什么时候跑**：一批涉及 Agent 路径的修复合入后跑一轮，比较总时长和重复出现的问题。没有退步、剩下的都是小问题就停，到下一个里程碑再跑。
- **验收标准**：修复的验收标准要写明必须覆盖的输入变体，例如所有接入通道。否则 MR 测试只覆盖其中一种，下一轮体验测试又会撞上。

## 坑

- **MR 里通过、上线后仍错**：接入状态只统计了 SDK 通道，体验测试查出来后返工。返工的验收改成"SDK、MCP、CLI 三个通道都算"，测试覆盖三条路径。
- **headless 浏览器看不到标签页图标**：网站图标只能用 HTTP 取文件、核对页面里的图标声明来验证。
- **宿主差异要写进接入文档**：例如工具暴露方式，以及 OAuth 客户端走动态注册还是客户端元数据文档。
- **外层 Agent 容易知道得太多**：要明确禁止它读源码仓库和历史测试记录，否则体验不真实。
