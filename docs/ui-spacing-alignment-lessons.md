# UI 间距与对齐：从截图修补到结构防线

当用户连续指出贴边、左缘不齐、筛选区杂乱时，先查谁拥有间距，再改数值。把错误写法从组件接口中移除，让门禁量页面关系，最后用真实截图验收；只统一变量名称或更新截图基准，无法阻止同类问题回来。

本文供维护共用 UI 的开发者和验收者使用，记录一次 2026-10-29 的跨页重构。来源包括六张用户反馈、按样式拥有者归因的盘点、合并版本的设计契约与门禁，以及两轮验收裁决；业务名词与项目标识已去除。下文数字是该轮例证，不是所有项目必须采用的尺寸。来源工作簿当时仍将部署和 UAT 前巡检列为进行中／待试跑，本文不把它们算作已完成效果。

## 1. 症状：六张截图，旧检查却逐页返回空

用户给出六张截图：操作贴着下一块内容、同级卡片内文起点不同、筛选字段落成孤立的一行、页签与表格首列不齐、提示与照片缺少间隔、筛选区贴表面左边。

盘点固定版本、1440×1000 CSS 像素视口、同一批代表性非空数据，结合 DOMRect 与 computed style，发现页面标题和主面板外框本来就在同一条线上；错位主要发生在表面内部。不能把所有现象归为“整页 margin 不对”。

在每个取证状态调用旧版面检查，结果全部为空。这只证明该函数没报错，不证明当时完整 CI 或视觉套件通过。后续重构首版则确实出现 CI 全绿、验收者亲自看图仍退回五项的情况。两者共同说明：检查成功必须连同检查覆盖的关系一起解释。

## 2. 根因：间距有多个拥有者，检查没有比较关系

| 模式 | 观察例证 | 为什么局部修补不够 |
| --- | --- | --- |
| 同一表面多个内距拥有者 | 页签、标题、筛选、表格分别使用 24／18／12／10／20／0px | 各段单看都合法，放在一起就产生多条内容基线 |
| 调用端绕过共用容器 | 裸表面加页签、手写 filters、按钮直接塞进片段 | 有共用包不等于调用端必经共用包 |
| 表面重复嵌套 | 同一任务的完整列表放进已有白色面板，产生第二层外框和缩排 | 单纯减 padding 会掩盖表面归属错误 |
| 兄弟块没有节奏拥有者 | 表格与照片、标签与提示之间为 0；相邻块各带 padding 又叠成 48px | 子组件的内部间距不能决定兄弟关系 |
| 门禁只看登记选择器 | 只量部分容器的直接子元素、最小内距；不比较跨容器左缘 | 深层按钮、表格首列、统计值等没进入检查范围 |
| token 使用只是局部习惯 | 约 400 处 padding／margin，只有约 30 处使用 token | 仍可在应用层任意创造数值与覆盖规则 |

旧结构检查记录标题、字段与顺序，不等于记录坐标关系；像素门禁把正式版与既有正式截图比较，既有坏版面也能成为稳定基准。原型和正式实现共用 CSS 时，还可能一起错。遮罩中的表格文字、数值位置，也不能靠像素通过证明正确。

## 3. 三层防线：减少自由度，发现逃逸，再由人裁决

### 框架层：让正确组合成为默认路径

**数值只定义一次。** CSS 间距文件提供标准档位，类型化的 `Space` 只允许这些档位；antd `ConfigProvider` 的 Card、Tabs、Table 等组件 token 从同一来源派生，不再维护另一份相似常数。桌面表面 24px、手机 16px、既有登录表面 48px 是该轮保留的角色区别，统一来源不等于所有角色同值。

**关系只由一个容器拥有。** `Stack`／`Page`／`Surface` 拥有兄弟 gap；表面拥有水平内距；纯时间组合列本身不带内外距。在页面中从页面内容线开始，进面板则由父容器提供一次内距。固定底部操作区按实际高度测量并留出空间，不用多套固定补偿值。

**接口表达角色。** 列表容器提供 toolbar、controls、content、table、footer 等类型化插槽，替代任意 children；控件网格只装字段，新增等动作通过 actions 插槽进入独立操作列。列表嵌入已有表面使用 `embedded`，独立子实体卡则可以保留自己的表面，外框对齐父内容线。不要一刀切禁止所有嵌套。

**表格也遵守表面契约。** 全宽表格首末列承接表面内距，中间列保留自己的密度；已包在带内距容器内的表格不再重复缩进。展开图标列、数据首列、单元格外框与文字起点要分别定义，不能见到不同 x 就判错。

**约束逃逸路径。** 应用层 ESLint 拦截 `style` 和白名单外 `className`，stylelint 要求 padding／margin／gap 使用 token；共用包负责受控实现。告警必须经统一检查命令转成非零退出，才能成为 CI 防线。白名单、别名和新增 token 仍要审查，不能成为另一个任意样式入口。

**旧值按用途退场。** 首版曾把手写数值改名为 legacy token，语法合规却没有统一布局。修正后 legacy 定义从 24 个减到 5 个、引用从 190 次减到 7 次；187 次间距属性引用减到 7 次。剩余仅为控件内部的微型偏移、徽章、图标操作空间，没有容器级例外。以文件及精确用途限制，禁止增长、跨文件借额度、未登记别名和闲置定义。棘轮的通用原则见[架构不腐化](architecture-anti-erosion.md)。

### 被动层：量不变量，并证明检查会失败

用页面语义与共用组件标记发现表面，替代逐页选择器登记。新页面使用标准组件即可继承量测；这不表示脚本能自动理解任何任意 DOM，缺少必需标记、绕过组件的路径仍由 lint 和检查自测兜住。

把设计契约写成关系，而不是“这个选择器至少留 23px”：

| 不变量 | 量什么 | 必须放过的合法情况 |
| --- | --- | --- |
| 表面内容边界一致 | 页签、筛选、表格首末列、标题、笔数、分页面向各自表面边界 | 多列网格第二列、表格展开列、不同角色表面 |
| 垂直节奏有拥有者 | 同组兄弟块的可见间隔，不只量单块 padding | 内容换行自然增高 |
| 单行字段基线一致 | 标签和控件上下缘，原生控件与组件库高度 | 多选／多行保持顶缘对齐并向下增长 |
| 嵌入与独立子表面可区分 | embedded 不重复画框；独立卡外框对父内容线 | 子卡内部可以拥有自己的内距 |
| 操作与字段分组 | 按钮进入 actions 操作列，不混进字段网格 | 字段自身必要的组合控件 |
| 信息完整可辨识 | 宽表末列、长说明、图说裁切及内部技术字符串 | 窄屏按设计保留水平滚动；明确标注的诊断编号 |

每条规则都要有负向自测：故意制造贴边、重复内距、错误嵌套、操作混排或图说截断，先看到失败，再修复为绿；同时保留合法换行等正向案例，避免把布局“统一”为不可用。还要在旧版真实页面运行新门禁，证明它能抓到原反馈，而不只是会抓人工构造的 fixture。

扫描可见技术字符串补足几何盲区。UUID、内部动态键等模式按产品实际定义，明确诊断例外；几何正确、扫描通过都不能替代人判断标签是否能区分对象。

### 流程层：让反馈回到防线

每条画面反馈都回答“哪条门禁本该抓到，为什么没抓到”，修同类调用端并补防线，再做截图验收。验收者亲自对照设计契约看图，不凭实现者摘要或 CI 接受。

共用 UI 重构或系统性画面反馈，可安排独立设计审查：冻结同版本、同数据、同视口、同滚动位置的前后图及 `DESIGN.md`，不提供实现摘要与作者自评。要判断相对原型退步时另附冻结的原型图；只给前后图不能宣称完整原型对齐。这里的关键是审查输入独立，而不是每次小改都增加一轮审查。

UAT 前全站截图巡检可作为候选版本的试跑：逐页看代表状态，记录能额外抓到什么，再决定是否常设。本轮只确认采用这一方向，尚无巡检收益数据，不把它写成已验证的固定流程。

## 4. 验收：数值修齐之后，还要看能不能读懂

首版 CI 全绿后，验收者退回五项：纯时间列仍缩进、独立子卡位置不对、原生与组件库字段有高差、控制区垂直空白叠加、legacy 只是改名。第二轮把这些问题分别变成真实入口红灯和负向自测。

| 验收证据 | 该轮变化 | 可迁移的判断 |
| --- | --- | --- |
| 纯时间列 | x 276→252，与页面起点一致 | 不带间距的组合列能在不同父容器复用 |
| 独立子卡 | 外框 x 269→277，与父内容线一致 | 外框和内文分层量，不强求同一 x |
| 单行控件 | 4px 高差→0 | 原生与组件库须共享高度契约 |
| 连续控制块 | 可见空白 48／40→16／16px | 量最终可见间隔，避免 padding 叠加 |
| legacy 引用 | 190→7 | 追踪用途与用量，不能只检查是否写了 var() |

独立设计审查又发现：网格从一行约 7 张变成约 10 张，缩略图仍约 96px，标签却收窄，多个内部键名都被截成相同前缀。密度提高使既有可读性缺陷变成更严重的问题。最终共用人可读标签，保留 160px 图说宽度、允许两行，并增加技术键与裁切负向检查。不能只靠缩字或 tooltip 让默认画面勉强过关。

同轮还修了操作混在筛选网格、数据表外框与头像差 4px。另一项“内容移出当前视口”的建议未采用：单张截图只能证明它不在当前屏内，不能证明被删或不可达；应补同滚动位置及底部证据，不能因此全局缩小间距。

最终记录包括 50 个视觉状态、32 个版面自测、17 个策略测试及 199 个前端单元测试通过；这些是该轮执行范围，不是复用时必须凑齐的数量。截图证据等待字体与图片解码，保持数据签名及滚动位置一致。JPEG 坐标只用于近似定位，精确 CSS 归因以 DOM 量测为准；合成图加载成功也不能证明原反馈中的真实附件始终正常。

## 5. 可直接抄的检查清单

按本次受影响范围选用，不把它变成每个小改都全跑的仪式。

- [ ] 固定修前／修后版本、代表数据、视口、滚动位置；记录未覆盖的状态。
- [ ] 从用户截图拆出关系错误，区分页面外框、表面边界、单元格外框和文字起点。
- [ ] 按拥有者盘点同类页：裸容器、重复表面、表格边缘、兄弟 gap、组件库默认 token。
- [ ] 间距只有一个数值来源；组件库主题同源；每个关系只有一个布局拥有者。
- [ ] 用类型化档位、插槽和 embedded 角色收窄调用端自由度；应用层样式逃逸会被 CI 拦截。
- [ ] legacy 有精确用途与逐文件棘轮；不以改名、别名或跨文件额度掩盖容器旧值。
- [ ] 每条新增不变量有先红后绿的负向自测，也放过合法换行、网格和独立子卡。
- [ ] 新门禁在原问题的真实入口失败，修后通过；明确它仍看不到什么。
- [ ] 每条反馈写清“本该由哪条门禁抓到”；修同一模式的其他调用端。
- [ ] 验收者亲自看受影响截图，检查长标签、末列、底端、展开态和默认可辨识性；遮罩区域另看原图。
- [ ] 系统性重构的独立设计审查只收冻结证据与设计契约；逐项裁决发现，不用实现摘要代替看图。
- [ ] 先完成设计验收再更新像素基准；UAT 候选巡检的结果与尚未执行项分开记录。

回到项目时，把具体数值和角色写进本项目的设计契约，把实现放在共用 UI，把失败条件放进门禁。本文保留跨项目的判断方法，不承接任何项目的尺寸真源或验收状态。
