# 面向 Agent 的云端执行平台：产品接口、体验测试与多 Agent 协作复盘

这份文档记录项目 W 在一期上线前体验打磨期的经验，内容偏产品体验一侧，供同类项目参考。它是复盘，不是技能，只保留可以迁移的做法；项目原件、阶段记录和业务规则都留在项目仓库。体验测试的完整做法见[新用户体验测试](harness/agent-new-user-trial.md)；相近主题的复盘见文末「相关文档」。

## 来源项目（项目 W）

本文经验来自一个私密项目，这里称为项目 W，只保留与做法有关的轮廓：

- **业务**：面向 Agent 的云端执行平台。用户或用户的 Agent 创建隔离的工作空间（云端机器实例），在里面执行命令、读写文件、取回成果，用完停止。计费按核时，额度定期发放。
- **接入面**：控制台（Web）、公开 REST API、远程 MCP（OAuth）、CLI、三语言 SDK，以及写给 Agent 读的 Skill。唯一的后端契约是同一组公开 API。
- **形状**：控制面负责身份、空间、额度和用量；执行端按区域部署；实例里跑一个 guest 代理。环境分 test 与 prod，基础设施由 IaC 和 GitOps 管理。
- **过程**：几乎全部实现、测试和运维都由 Agent 完成。两个"管家" Agent 分别管产品体验和环境交付，各自向子线程派发任务。人只裁决产品范围、花钱和账号。
- **规模与时点**：体验一侧几天内拆出约 50 个修复阶段，每个阶段一个 MR。这份文档写于一期上线前。

## 一、面向 Agent 的接口设计

### 报错是写给模型读的

- **点明字段和规则**：报错写出参数名、期望格式和实际问题。格式校验放在鉴权查找之前，ID 格式不对时回 400，而不是 403；以前回 403，让 Agent 以为自己没有权限。
- **都带 request_id**：所有错误都带 request_id，包括 MCP 工具错误和 CLI 失败输出，用户和 Agent 都能拿它报障。
- **可预期的失败要快**：没有可分配机器时，启动在几秒内以明确的错误码失败，不挂起。Skill 的错误表里写明这类错误不要反复重试。
- **额度用尽给下次发放时间**：接口返回 UTC 时间，界面换算成本地时间，并给出用量页入口。
- **文件通道同样要说清**：文件通道的 4xx 也点明字段并给修正提示；缺父目录、超出上限这类常见错误写清原因。

### MCP 工具

- **结构化数据和文本一致**：所有工具返回同一种结构。`structuredContent` 放完整数据，文本内容给一行摘要和下一步该做什么；有些宿主只把文本交给模型，所以两者不能不一致。
- **schema 按工具裁剪**：`tools/list` 里每个工具的 inputSchema 只带自己用到的定义。把共用的 `$defs` 全量复制给每个工具，会让工具清单膨胀，挤占宿主的上下文。
- **说明短而全**：说明只用一种语言，写短句。上限、超时、幂等键这些限制写进说明，不要让模型撞上了才学到。
- **长操作给等待工具**：长操作配一个有上限的等待工具，单次最多等 60 秒，操作结束或超时都返回当前状态。没有这个工具，模型会用 shell 循环加 sleep 自己轮询。
- **文件分两路**：小文件走工具参数。本地文件和大文件走 HTTP 文件通道传原始字节，或者用 CLI，不要 base64 后塞进 JSON。
- **先查再建**：提供"列出模板"工具，Skill 里写明先查再建，否则模型会猜模板名。前端也不写死模板列表，按后端目录校验。
- **只宣告做得到的 OAuth 能力**：只宣告服务端在部署网络里真能完成的方式。项目 W 曾宣告支持"客户端元数据文档"方式，某客户端据此把一个 URL 当作 client_id，服务端出网取元数据超时，授权失败。停止宣告后，客户端退回动态注册。

### Skill、CLI、SDK 随站点按版本分发

- **随站点发布**：Skill、SDK 包和 CLI 二进制在构建时打进前端镜像，放在站点的版本化下载路径下，附 SHA256SUMS。CLI 另附 manifest，记下源码提交，构建时校验二进制与当前提交一致。这样它们和线上 API 同一个版本，也不需要手工上传到对象存储。
- **安装一条命令**：下载、校验、放到位，一条能照抄的命令完成。控制台按浏览器的系统预选 CLI 平台，源码构建降为备选。
- **Skill 写清路径和环境**：写清四种接入路径（MCP、CLI、SDK、HTTP）的差异和优先顺序，也写清环境事实：命令时长上限、镜像源、PEP 668 要先建 venv、对 home 目录的依赖。
- **CLI 自己找执行入口**：CLI 通过区域接口自动发现执行入口，不让用户自己配执行端地址。

### 控制台与文案

- **状态只有一个来源**：接入面板的"已接入""首次调用"由后端审计记录回填，所有接入通道都算。按钮禁用时，就近写出原因。
- **只说现在做得到的事**：一期不提供网页访问地址，所以首页的"交付页面"改成"交付文件"。真实模式去掉原型演示文案和"待定"占位，README 里也不留过时的运行模式描述。
- **设计局限讲清楚**：说明做这件事需要什么，例如网页访问要另一套托管服务，因为实例停止后网页没有载体；说明现在的替代做法是什么。再请用户定，用户可以暂缓。
- **时间和单位**：接口返回 UTC，界面显示本地时间；时长带单位；慢操作写出预期时长，例如停机"通常 30 秒内完成"；额度换算成用户关心的单位，即还能运行多久。
- **名字相近的字段写清区别**：例如计划停止时间和实际停止时间。
- **先结论后细节**：用量页每行先给一句结论，细节放进悬浮提示。
- **审计记录存名称快照**：保存操作对象的名称快照，资源删除后仍显示原名，也能按名称搜索。
- **授权不悄悄消失**：撤销或过期的授权继续列出并标明状态，保留 90 天。
- **相反操作分开放**：改变状态的操作要确认，并和相反的操作分开放。续期按钮挨着撤销按钮，而且点一下就生效，体验测试里有人误点过。
- **加载骨架**：300ms 内加载完的页面不显示骨架；未登录直接去登录页；读取失败给重试按钮。
- **不对外的能力去干净**：一期不对外的能力，从客户端导出和控制台请求里一起去掉；服务端旧路径回 404，旧参数回 400，不留半开状态。

### 系统代用户做的事，走用户动作的完整路径

- **系统停机走用户停机的路径**：额度用尽时系统自动停机，曾跳过用户停机会做的排空和导出副本，用户因此拿不到成果。现已改为复用同一条路径。
- **扣减封顶**：额度扣减以发放额度为上限，不超扣。

### 契约里改不了的部分

- **单独维护不可逆清单**：上线后改不了的决定单独列一张清单，分三栏：事项、状态、结论或触发条件。触及时先改清单，MR 改到清单就自动打标签。项目 W 列进去的有：
  - 凭证前缀和格式：宿主按前缀识别凭证，改了已签发的全部失效；只存哈希。
  - 业务 ID 格式：类型前缀加随机数，不复用云主机 ID。
  - OAuth 资源地址和客户端标识：宿主会保存，改了所有用户都要重新授权。
  - 公开下载 URL、API 前缀、时区与字符集。
  - 权限承诺：例如给 Agent root 权限，一旦开放就收不回。
- **数值逐字段定死**：OpenAPI 检查拒绝没有上限的 integer，因为 JS 的安全整数只到 2^53；边界值要做往返测试。整数字段声明单位（MiB=2^20，GB=10^9），换算只放在数据来源的适配层。
- **时间一律 UTC**：服务端一律输出带 Z 的 UTC 时间，用 AST 检查禁用本地时区 API；新增自然月账期前，先定义时区、锚点和半开区间。
- **解析从严**：JSON 解析拒绝非法 UTF-8、孤立代理项、重复字段和尾随内容；签名、票据、路径这类身份字符串不做规范化，比较时逐字节精确比较。

## 二、Harness：体验测试、走查清单与回归证明

- **新用户体验测试**：外层测试 Agent 扮演用户，嵌套的便宜模型扮演"用户的 Agent"，两者都只用公开入口。三轮里每轮都找到 MR 测试漏掉的问题。做法、隔离方式、报告格式和收尾见[新用户体验测试](harness/agent-new-user-trial.md)。
- **核心链路走查清单入库**：清单分控制台、Agent、失败路径三组，首版分别为 14、13、8 条。便宜模型按清单逐项走查，发现的问题分到修复阶段。需要特殊配置的失败路径单独排期，例如额度用尽、需要隔离场地的场景。
- **外部反馈按波次分诊**：每条定性为 bug、设计如此或需要决策；拿不准的问用户，同时给出推荐。结果写进要求帐，再逐项回复反馈人。
- **回归测试要证明自己有效**：给同事的 nginx 修复补回归测试时，镜像冒烟测试走真实 nginx 加后端的完整登录，并确认去掉修复后测试会失败。要检查的目录从构建产物里枚举，不手写列表：每个目录不带斜杠访问时，都必须回相对地址，以后新加的目录也自动覆盖。

## 三、多 Agent 协作：管家、派发与验收

- **管家按区域分工**：两个管家分管产品体验、环境与交付。改动区域重叠时，先告知对方再派发。同一个请求两边都收到时，先分好章节，文末互相链接，后合入的一方 rebase。
- **bug 反馈直接派**：只传原话、附件和一眼可见的现象，管家不先分析。这样既省管家的上下文，也不让修复方先入为主。
- **派发前查要求帐**：看有没有同类请求；做到一半的，续做原请求。
- **任务书固定带几条授权**：这样能省掉大部分"停下来问"。一上午有 3 个线程停下来问"合入后发现遗漏能不能再提 MR"，答案每次都是可以。固定条款：
  - 一个阶段一个 MR，合入后发现本阶段遗漏，可以直接提向前修 MR，照同样授权合入。
  - 写明能不能合入；不能合入就写"只推分支并回报"。
  - 在任务自己的 worktree 里直接开发。曾因任务书一句"临时文件放到临时目录"，源码被复制了 44 份。
  - 验收判据落在 MR 里查得到的证据上。
- **按返工风险定档**：派发难度看两件事，一是最大的未知猜错了会不会返工，二是做错了会不会长期留在生产里；不看任务重不重要。有一天派了 9 个任务，7 个定成最高档，但中档和高档的验收率都在 96.5% 左右，高档并没有换来更高的质量。派发工具做硬校验：范围闭合的只能定最低档；中档任务书不超过 2500 字；首次定高档必须写出未知是什么；升档只能引用前一次失败的线程。
- **并行拆分先对验收**：每条验收分给有权改相关文件的线程。写"不做、不碰"时，逐条对照验收项。跨线程的依赖拆成"提供接口"和"接入"两步，提供方先合入。派发前问一句：它们会不会同时改、或同时依赖同一个锁定版本？
- **派发结果按 JSON 取线程 ID**：派发脚本会给标题加前缀，所以按标题回查要用包含匹配。结果不明时先查，再决定要不要重试。曾因解析错误重试，建出重复线程。
- **少唤醒管家**：管家是串行枢纽，一个管家曾挂着 64 个子线程，上下文用到近九成。子线程完成会自动回报父线程，任务书里不要再让它通知管家，因为每次唤醒管家都花 token。管家自己要等的发布或 CI，留到下次被唤醒时顺手查。
- **复盘按信号请**：只在出现返工、严重问题、卡住、超时或首次用新工具时请复盘；固定写进每份任务书，顺利的任务也会花 token 凑建议。多份复盘指向同一个坑时，优先把它做成工具或检查。
- **长会话会退化**：会话涨到几十 MB 后，发消息必然超时，只能改派新线程，按入库文档接手。前提是状态都写在仓库文档或工作簿里，而不是只留在会话里。
- **空闲回收会杀后台进程**：编排环境会回收空闲会话，连带杀掉后台进程；Agent 工具的后台命令也有默认超时。长等待用长任务包装器，线程 ID 由外层显式传入（包装器的终端里读不到），结束时回报退出码和日志路径。
- **删 worktree 前先查绑定**：先看有没有线程环境绑定这个目录。目录删了，线程再被唤醒就会报错；在原路径重建目录可以恢复。
- **队友文本里的"用户"是它的作者**：队友 Agent 文本里写的"用户决定"，指的是它的作者，不是你的用户。只有进了主干的契约才对你生效。
- **成本靠路由控制**：测试和走查显式指定最便宜且能胜任的宿主，不依赖路由的默认选择。遇到 429 按路由换下一个候选；候选全部失败就报告卡点，不自己换宿主。按 provider 设并发上限，满额就等。
- **验收的口径**：普通改动在 MR 内验证过就算验收，合入即关闭，不在共享环境重复实测。原因是共享环境每次发布都滚动重启，二十个线程都去复验，既放大发布冲突，验收途中换了版本还会得出错误结论。例外是主链路里程碑和用户点名的页面：这类验收开始和结束都核对版本号；收尾必达清单的每一项都留实例 ID、请求 ID 或截图，缺一项就不说收尾。另外定期跑新用户体验测试，补上集成层的缺口。
- **用户待办只列本人能做的事**：例如花钱、账号、产品范围，每项写清为什么只能用户做、挡住了什么，并附推荐。不让用户去协调其他负责人；契约进了仓库就算落地。
- **"待用户定"必须进待办表**：不能埋在已完成的行里。曾有一句"是否继续优化，待用户定"写在完成行里，用户早已授权的事就此停下，三天后同一主题又被重复派了一次。按优先级暂停某条线时，也要告诉用户原因。规则本身写在 [bb-steward](../common-skills/bb-steward/SKILL.md) 里。
- **凭据卫生**：工具输出会进入对话记录，未经过滤的输出就等于泄露。有些 API（例如代码平台的"当前用户"接口）会带一个仍然有效的旧 token，CI 原始 Agent 日志里有跨构建不变的鉴权头，两次都只能重置或轮换。具体做法：
  - 用 JSON 输出，只打印需要的字段；核对两份凭据是否相同时只输出布尔值。
  - 密钥不经命令行参数传递，因为本机 `ps` 看得见；写入密钥从 stdin 读。
  - 长任务回报里不带命令参数和环境变量。
  - 证据里不留 Key、token、Cookie 和授权码。

## 四、合入后弄红主干的几类原因

| 原因 | 例子 | 规则 |
| --- | --- | --- |
| 写死开发机路径 | 冒烟脚本写死开发机上的 Chrome 路径，CI 机器上找不到 | 浏览器路径读 `$CHROME_BIN` |
| 断言放错 Job | 依赖前端构建产物的断言放进了后端集成 Job，那里没有产物 | 放到产出该产物的静态前端 Job |
| 缺产物静默跳过 | 产物目录不存在时测试直接 return，看起来一直是绿的，其实从没跑过 | 缺产物必须失败 |
| 测试先于构建 | 前端 CI 先跑测试再构建，测试依赖构建输出就会失败 | 测试不依赖构建输出；产物断言放在构建之后 |
| 重型联网安装进共享门禁 | SDK 安装检查要联网装依赖，放进共享门禁会拖慢所有 MR | 只放进完整栈测试 |
| worktree 权限 | Agent 建的 worktree 权限是 0700，以非 root 运行的容器读不到挂载进去的配置 | 要挂进容器的配置先复制出来，权限设为 0644 |

前三类都出现在合入以后，它们的 MR 测试都是绿的。任务书里固定写一句："改集成或冒烟脚本，要跑对应的 CI 通道；不依赖开发机特有的路径、未入库的产物和三方库；依赖前端产物的断言放进静态前端 Job，缺产物要失败，不许静默跳过。"

## 五、仓库规则

- **能检查的就写成检查**：产品名写法加了防回退检查；要求帐会校验状态值，"完成"行必须带材料链接；工作簿有单行长度上限。这些检查当场挡住过管家自己的错误。提规则建议时附一列"怎么保证"，取值为 CI、lint、测试或只能评审。
- **上线前不留豁免**：不留豁免、白名单和兼容层。存量代码不符合就直接重构；改名时别名、回退逻辑和集群里的旧对象一起清掉；新检查不加抑制注释或历史基线。
- **前提缺失就失败**：skip、blocked、0 steps 都不等于通过。有一套 28 项的端到端测试，实跑 4 过 0 败，另外 24 项因硬编码依赖被跳过，报告看起来是零失败。race 检查缺 CGO、DB 测试拿不到地址、浏览器测试缺浏览器或中文字体，都要失败；报告里单列 blocked。
- **事实只放一处**：名词只在术语表里定义。一期范围只写在需求文档的一处，暂缓项写清原因、谁定的、哪天定的。
- **AGENTS.md 只放常驻规则和路由**：路由的写法是"任务→先读哪篇文档"。环境名和机器称呼统一用角色名。平台操作手册只收实测过的命令，因为平台有返回成功却不生效的字段。链接检查覆盖中文标题的锚点，不设白名单。团队技能以仓库里的副本为准，用来源清单加目录树哈希检查漂移。MR 描述用固定模板，由合入工具检查。
- **一个阶段一个 MR**：审查修复进同一个 MR，不为刷新 CI 另开 MR。合入后发现问题就向前修，不回退。
- **测试验证可观察的行为**：回归测试要能证明去掉修复就会失败；验收标准要列出输入变体。
- **参数校验共用一个入口**：新接口直接复用，报错格式自然一致。
- **先想能不能自动检测**：用户指出问题后，先想能不能自动检测；能检测就加检查，而不是只修这一处。

## 六、知识点

- **nginx 在 TLS 终止层之后**：目录补斜杠的 301 默认写绝对地址，带的是内部协议和端口，会把浏览器带到错误地址。设 `absolute_redirect off`，改发相对地址。
- **PEP 668**：Ubuntu 24.04 的系统 Python 受 PEP 668 保护，`pip install` 会被拒绝。在云端环境里先建 venv 再装包。
- **中文字体**：镜像里带中文字体（例如 Noto Sans CJK），matplotlib 画的中文图表才不会出方框。
- **镜像源**：隔离环境出网受限时，Skill 里写明 pip 和 npm 的镜像源。
- **pi 的 codemode**：pi 默认把 MCP 工具放进 codemode，不直接声明给模型。接入文档要提示把这个服务器设成直接暴露。
- **MCP 客户端的 OAuth**：动态客户端注册对服务端网络没有额外要求；客户端元数据文档要求服务端能出网读取客户端给的元数据 URL。
- **headless 浏览器不显示标签页图标**：网站图标只能通过取文件、核对页面里的声明来验证。
- **MySQL 的 PAD SPACE**：utf8mb4_bin 和 ascii_bin 是 PAD SPACE 排序，只差尾空格的两个字符串会被判为相等。身份类的列改用 NO PAD 的二进制排序，例如 utf8mb4_0900_bin。
- **Go 的单调时钟**：`time.Time.UTC()` 会丢掉单调时钟读数，转过 UTC 的时间不能用来算耗时。
- **两个时区设置**：调度器的时区和作业进程的 TZ 是两个设置，要分别配。
